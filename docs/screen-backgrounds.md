# 포토부스 · 키오스크 공통 배경 관리

## 매장 사용

- `/admin/backgrounds`에서 두 기기의 배경을 함께 관리합니다. 기존 포토부스·키오스크 관리 페이지에도 진입 링크가 있습니다.
- 이름, 이미지 교체, 글꼴 조합, 글자/강조/바탕색, 순서, 노출 여부를 수정할 수 있습니다. 새 배경 추가와 삭제도 지원합니다.
- 기기 우측 하단을 누르고 관리자 PIN `110619`를 입력하면 같은 목록에서 배경을 선택합니다. PIN은 서버에서 검증합니다.
- 적용 배경은 **기기 종류별 공유**입니다. 포토부스에서 바꾸면 다른 포토부스에도 반영되고, 키오스크의 선택에는 영향을 주지 않습니다.
- 켜져 있는 기기는 15초마다 갱신합니다. 관리자 메뉴를 열거나 화면으로 돌아오거나 네트워크가 복구되면 즉시 다시 조회합니다. 오프라인에서는 마지막으로 받은 설정을 유지하므로 다시 연결되어야 수정·삭제가 반영됩니다.
- 현재 배경을 숨기거나 삭제하면 다음 노출 배경으로 전환합니다. 전부 숨김/삭제하면 중립 바탕을 사용하며, 삭제한 기본 배경을 자동으로 되살리지 않습니다.
- 삭제는 중앙 목록에서의 제거입니다. 생성 원본과 업로드 이미지 파일은 복구 가능하도록 보존하며 실제 사진·인화 프레임·분석 영수증에는 영향을 주지 않습니다.

## 레트로 UI 테마와의 관계 (2026-09)

`/booth`와 `/kiosk`의 화면은 **레트로 데스크톱 UI 테마**(파스텔 블루·라일락, 파란 그라데이션 타이틀바, 입체 테두리, 픽셀 아이콘, 블록형 진행 표시)로 고정되어 있습니다. 배경 선택과 UI 테마는 별개입니다.

- **배경 = 바탕화면.** 선택한 배경 그림은 창 뒤의 바탕화면으로만 깔립니다. 창·버튼·입력란·진행 표시·대화상자의 색은 `src/components/retro/retro.css` 토큰으로 고정되어, 어떤 배경을 골라도 기능 UI의 대비와 모양이 같습니다. 이미지에 기능성 글자나 버튼을 그려 넣지 않습니다.
- 배경별 설정은 아래 역할로만 쓰입니다. 변환은 `toRetroDesktop()`, CSS 변수는 `retroDesktopVars()`가 맡습니다(`src/lib/screen-backgrounds/theme.ts`).

| 관리자 설정 | 레트로 UI에서의 역할 | CSS 변수 |
|---|---|---|
| 배경 이미지 | 바탕화면 그림 | `--rt-wallpaper` |
| 바탕색(base) | 그림이 뜨기 전·빈 곳의 바탕, 바탕화면 아이콘 이름 받침 | `--rt-desk-base` |
| 글자색(ink) | 바탕화면에 바로 놓인 글자(아이콘 이름). base 대비 4.5:1로 보정 | `--rt-desk-ink` |
| 강조색(accent) | 장식: 창 뒤로 겹친 창 테두리 등. 기능 UI에는 쓰지 않음 | `--rt-deco`, `--rt-deco-soft` |
| 글꼴 조합(palette) | 창 안 한글 큰 제목 글꼴 + 본문 글꼴 | `--rt-display-font`, `--rt-body-font` |
| 톤(tone) | 바탕화면 글자 받침의 밝기 판단 | `data-tone` |

- 픽셀 서체(Silkscreen)는 타이틀바의 짧은 영문 제목과 숫자에만 쓰고, 한글 안내·본문은 글꼴 조합의 본문 서체를 씁니다. 키오스크의 일본어·중국어는 Noto Sans JP/SC/TC로 바뀝니다.
- 포토부스 이벤트(생일카페)의 테마색은 장식색 자리에만 들어가고, 사진 합성·인화 캔버스의 이벤트 색은 그대로 유지됩니다.
- 기존 `toKioskTheme()`·`toBoothTheme()`의 출력은 바뀌지 않았습니다(검증 테스트 그대로). 관리자 미리보기와 기기 관리자 배경 목록의 글꼴 미리보기가 계속 사용합니다.
- 공통 부품: `RetroWindow`(창), `RetroDialog`(작은 대화상자), `RetroProgress`(블록 진행 표시 — 진행률을 모르는 작업은 움직이는 블록만, 퍼센트를 만들지 않음), `RetroSteps`(단계 칸), `PixelIcon`(16×16 픽셀 아이콘, 이모지 대신), `RetroDesktopIcons`·`RetroStickers`(장식, 터치를 받지 않음). 모든 규칙은 `.rt` 범위 안에서만 동작해 일반 웹사이트에 영향을 주지 않습니다.

## 등록된 이미지

각 기기 36종: 실제 포스터 기반 20종 + 앞선 리뷰 시안 10종 + 기존 배경 6종. 총 72개 항목과 144개 WebP(배경/썸네일)를 제공합니다. 같은 콘셉트의 가로·세로 항목은 각각 편집합니다.

- 포토부스: 1920×1080, 16:9
- 키오스크: 1080×1920, 9:16
- 최신 키오스크 20종은 별도 세로 구도 원본을 사용합니다. 이전 가로형 자료 16종은 중앙 크롭으로 맞췄으므로 가장자리 장식이 일부 잘릴 수 있습니다.
- 원본과 변환 내역: `design-review/screen-backgrounds-asset-report.json`
- 웹 에셋 재생성: `node scripts/prepare-screen-backgrounds.mjs`

## 중앙 저장 구조

`src/lib/screen-backgrounds/catalog.json`은 기본 카탈로그입니다. 관리자 수정 내용, 사용자 업로드 항목, 삭제 표식, 기기별 선택은 Supabase의 **비공개 `screen-background-settings` 버킷** `config-v1/`에 저장됩니다. 서로 다른 항목은 각각 저장하여 다른 관리자 편집을 덮어쓰지 않습니다. 같은 항목을 동시에 수정하면 마지막 저장을 적용합니다.

사진 업로드는 기존 공개 이미지용 `admin-content` 버킷을 사용합니다. 설정 읽기·쓰기는 서버 서비스 역할로만 수행합니다. 공개 API는 비밀정보 없이 해당 기기의 노출 배경만 내려줍니다. 기기 PIN 세션은 10분짜리 HttpOnly 쿠키이며 배경 선택 권한만 갖고, 수정·추가·삭제는 로그인한 웹 관리자만 할 수 있습니다.

새 Supabase 프로젝트로 옮길 때:

1. `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`를 설정합니다.
2. `node scripts/bootstrap-screen-backgrounds.mjs`로 비공개 설정 버킷을 만듭니다. 기존 버킷/설정은 덮어쓰지 않습니다. SQL 마이그레이션은 없습니다.
3. `admin-content` 이미지 업로드 권한은 기존 관리자 이미지 기능과 동일하게 설정합니다.
4. 필요하면 `SCREEN_BACKGROUND_ADMIN_PIN`(6자리), `SCREEN_BACKGROUND_SESSION_SECRET`를 서버 환경변수로 지정합니다. 세션 비밀키가 없으면 서버의 서비스 역할 키를 사용하며 클라이언트에 노출하지 않습니다.

PIN 시도 제한은 서버 프로세스별 분당 8회입니다. 다중 인스턴스에서 엄격한 전역 제한이 필요하면 공유 rate-limit 저장소를 추가해야 합니다.

## API · 검증

- `/api/admin/screen-backgrounds`: GET 목록, POST 추가, PATCH 수정, DELETE 제거, PUT 종류별 적용
- `/api/screen-backgrounds?target=booth|kiosk`: 공개 노출 목록과 선택
- `/api/screen-backgrounds/unlock`: POST PIN 검증
- `/api/screen-backgrounds`: PUT 기기 관리자 선택

`node scripts/verify-screen-backgrounds.mjs`는 카탈로그·규격·폰트·색상 대비·삭제 유지·인증·쿠키·에러 처리·기기별 선택을 검사합니다. 저장/API 테스트는 메모리 모형을 사용하고 운영 데이터는 변경하지 않습니다.
