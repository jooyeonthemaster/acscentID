# POST! 우체통 포토부스 — 프로그램 초안 (2026-11-22, 화면 다시 짬 11-23)

우체통 모양 포토부스에 들어갈 프로그램의 첫 초안. 기존 부스 프로그램 묶음(`src/app/booth/programs`, catalog)에는 아직 넣지 않은 **독립 화면**이다.
기획 원문 · 엽서 시안 · 화면 시안 · 목소리 원본: 바탕화면 `네안데르_크리스마스_부스/POST_기획/`. 실물 설계: 같은 폴더의 `우체통·공중전화_포토부스_구현계획_v2.pdf`.

## 화면 — 「우체통의 얼굴」(디자인 B, 11-23)

화면이 곧 우체통 「한통」의 얼굴이다. 기획 · 목업: 바탕화면 `POST_기획/단계별목업_B_가운데얼굴_손/`, 시즌 레이어 설계 `POST_기획/시즌레이어_설계.md`.

- **눈** (`Eyes.tsx`) — 화면 정가운데 고정, SVG 로 그린다. 남색 잉크 눈매(무거운 윗눈꺼풀 · 눈가 주름) + 회색 털 눈썹(고정 난수 획 — 서버 · 브라우저 같은 숫자가 나오게 소수 둘째 자리 반올림). 표정 12가지(idle · look · up · down · right · glance · read · happy · closed · wink · surprised · listen)를 숫자 값으로 0.35초에 옮긴다. 3~6초마다 깜빡이고, 우체통이 말하면 눈썹이 들썩인다.
- **손** (`Arms.tsx`, 그림 `public/assets/post/hands/*.webp`) — 화면 좌우 끝에서 남색 소매(빨간 테) · 흰 장갑이 들어온다. **손등이 화면 쪽**(11-23 다시 그림 — 우체통의 손이니까). 포즈 10가지(hold · fan · point_up · point_down · wave · cup · stamp · pen · phone · salute)는 Gemini 3 Pro Image 로 자홍색 바탕에 그려 바탕을 지운 것(원본 · 스크립트 `POST_기획/손그림_원본/v2/` — gen_hands_v2.sh → install.sh). 왼쪽 팔로 그렸고 오른쪽은 뒤집는다. 팔은 「쥐는 점(grip)을 무대 어디에」로 놓는다 — install.sh 가 `POSES` 의 grip 을 다시 잰다(fan · phone 은 key_v2.py 에 손으로 잰 값).
  - **쥐는 손(hold)** — 그릴 때 쥔 물건을 초록(#00FF00) 판으로 그려 그 자리를 비웠다. grip = 그 판의 아래 모서리. 화면에서는 진짜 엽서 · QR · 카메라 화면 · 우표를 그 모서리에 맞춰 손 그림 **뒤**에 깔아, 손가락이 앞면 모서리를 덮어 쥔다(`hold()` — 손도 물건과 같은 각도로 기운다). 손가락이 덮는 아래 모서리(높이 160 에서 약 90×75)는 중요한 글을 피한다 — 그림엽서는 오른손(지명이 왼쪽 아래), QR 카드는 위로 붙임.
  - **부채(fan)** — 받는 사람 태그는 손에 든 카드처럼 주먹 속에서 부채꼴로 펼치고 글은 바깥 끝에. 문장 고르기는 부채로 펴면 서로 가려서 양손이 메모 카드를 한 장씩 든다.
  - 눈 자리(무대 x 340~945, y 230~390)에는 손 · 물건을 두지 않는다 — 11-23 눈을 1.35배 키우고 사이를 넓혀(눈 가운데 x 465 · 815) 오른손 물건(QR · 사진 · 북극 표시)을 바깥 · 아래로 옮김.
- **바탕 = 우체통 빨강**(11-23 사용자) — 무대 바탕은 우체통 색(#c8202a, 가운데 밝게 · 가장자리 어둡게). 바탕 위에 바로 놓이는 글은 크림색, 화살표 · 숫자 · 귀 안내는 금색(`--po-on` · `--po-hi`), 눈썹은 흰 털, 로고는 크림 바탕에 빨간 글. 종이 · 태그 · 카드 위 글은 그대로 남색.
- **크리스마스판 = 산타에게만**(11-23 사용자) — 받는 사람 고르기 없이 시작하면 바로 휴대폰 연결(start_santa 대사), 넣으면 북극 → 답장 → 인화 엽서가 산타 답장. 제목 「산타 할아버지께 편지 부치고 가세요」, 대기 대사 idle_santa, 문장 고르기 예문도 소원 위주. 단계 표시 첫 칸은 「휴대폰」.
- **3D 광장(neander-booth-idea) 안에서** — iframe 이면 `post:scene` · `post:count`(카운트 시작) · `post:flash`(찰칵) · `post:print`(엽서 JPEG) · `post:escape` 를 부모에 postMessage. 인화는 부모가 3D 출구로 내보낸다.
- **미리보기가 멈추면** — 0.5초마다 확인해 다시 재생, 1.5초 넘게 멈춰 있으면 미리보기 위에 「눌러서 카메라 켜기」 + 상태 한 줄(정지/재생 · readyState · 해상도 · 트랙 상태). 사진은 미리보기가 실제로 흐를 때까지(최대 30초) 기다렸다 찍는다.
- **크리스마스 레이어** — `season='xmas'` 하나로: 눈썹 위 눈 · 눈동자 반짝임 · 호랑가시 · 눈발 · 금빛 번짐 · 초록 보조색 · 받는 사람에 산타 · 북극 흐름 · 끝 인사.

## 흐름

대기(화면 터치) → 받는 사람(양손에 태그 부채, 크리스마스는 산타 포함 8개) → 휴대폰 연결(QR · 건너뛰기) → 사진 한 번(그림엽서 앞면 + 같은 사진에서 자른 얼굴 우표, MediaPipe 얼굴 찾기)
→ **오른쪽 귀에 속삭이기**(버튼 없음) 또는 문장 고르기 → 받아 적은 글 확인 → **엽서를 위로 밀어 넣기**(밀기 어려우면 눌러 넣기) → 바로 받기(「아래에서 받아 가세요」 · 휴대폰 배달) → 인사.

- **넣은 뒤 바로 받기(11-23 사용자)** — 접수 · 소인 · 분류 · 배달 준비 장면은 없앴다. 엽서 JPEG · 인화 · 업로드는 받기 · 인사 장면 뒤에서 이어지고, 다 끝나야 처음으로 돌아간다(`finish` 가 기다림). 휴대폰 안내는 올리는 동안 「엽서를 올리는 중…」.
- 산타에게 보내면 넣은 뒤 「북극으로 보냈습니다」 → 답장을 받으면 「어, 벌써 답장이 왔네요?」 → 받기(인화 엽서가 산타 답장).
- 쓰지 않게 된 대사 proc_1~4 의 mp3 는 아직 남아 있다.

- **귀 마이크** (`record.ts` openEar) — 기기 오른쪽 옆면 마이크. 듣기를 시작하면 바로 녹음을 켜 두고, 첫 0.6초로 바닥 소음을 잰 뒤 그 2.6배(최소 0.07) 넘는 소리가 0.12초 이어지면 말 시작, 1.4초 조용하면 끝. 말한 구간 앞 0.45초 · 뒤 0.35초를 붙여 잘라 16kHz WAV 로. 숫자는 쇼핑몰 현장에서 다시 맞춘다. 귀 기울이는 동안 위쪽 빛 띠가 숨 쉬고, 듣는 동안 마이크 크기로 빛난다.
- **말하는 것은 우체통 「한통」** — 대사 39줄(ElevenLabs Sung-ho `AgA5UKT9OrVg7jxVBZd4`, eleven_v3)은 `public/assets/post/voice/<id>.mp3`, 글은 `src/app/booth/post/lines.json`. 11-23 버튼을 없애며 cam_ask(모자 배지 카메라) · post_ask(위로 밀기) · say_deaf(귀 가까이) 다시 녹음, ear(귀 안내) · bye_xmas 추가.
- **투입구 LED** — 말소리 크기를 `onLevel`(sound.ts)로 0~1. 화면 위쪽 빛 띠로 흉내만 낸다(실물은 부스 앱에 LED 기능을 더해야 한다).
- **시간 초과** — 15초 무응답이면 안내 한 번, 45초면 처음으로. 시험용 키: Enter 시작 · ↑ 넣기.

## AI · 키 · 비용

- 글에만 AI: 받아쓰기 + 맞춤법만 다듬기 + 줄 나누기 + 이름 뽑기 + 막을 말 거르기를 **한 번에**(오디오를 Gemini 3 Flash 에 바로), 약 2~5초 · 한 번 약 0.0009달러. 산타 답장 한 번 더. 사진은 AI 로 바꾸지 않는다.
- 산타 답장 규칙(선물 약속 금지 · 무거운 소원은 들어 주기만)은 `ai.ts` 프롬프트에.
- 키: `OPENROUTER_POST_API_KEY`(로컬 `.env.local` 에 R&D 키 STUDIO_RND_DONGJU 값). 프로젝트 · 고객 행사가 정해지면 그 키로 바꾸고 Vercel 에도 넣는다(아직 안 넣음).

## 초안이라 아직 안 된 것

1. **저장이 서버 임시 폴더**(`os.tmpdir()/acscent-post`) — 개발 서버 한 대에서만 맞다. 운영 전 Supabase 표(세션 · 엽서) + 저장소(그림 · 목소리, 보관 기간)로 바꾼다.
2. **카카오톡 공유** — `NEXT_PUBLIC_KAKAO_JS_KEY` 가 있으면 카카오 SDK(`Kakao.Share.sendDefault`)를 쓰고, 없으면 휴대폰 공유창(`navigator.share`)으로 대신한다. 카카오 개발자 앱(「AI우체통」 이름 권장)과 도메인 등록이 필요. SDK 버전(`PhoneClient.tsx` KAKAO_SDK)은 카카오 문서로 확인할 것.
3. **인화** — 부스 앱(window.boothShell)이면 `print(jpeg)` 로 바로, 브라우저면 건너뛴다(화면에 표시).
4. **이용권 · 결과 저장(손님 단위 기록 · 보고서)** — 기존 부스 흐름(pass-policy · program_shots)과 아직 안 이었다.
5. 이름 받아쓰기가 틀리기 쉽다(서윤 → 서연) — 확인 화면에 크게 보여 주고 다시 말하게 했다. 더 필요하면 이름만 따로 묻는 단계나 화면 키보드.
6. 개발 서버 화면 왼쪽 아래 「1~2 Issues」는 MediaPipe 가 정보 메시지를 console.error 로 찍는 것과 DSLR 브리지 확인 실패(웹캠으로 넘어감)다(동작 문제 아님).
7. 손님이 다가오면 알아보는 것(카메라로 사람 감지)은 아직 없다 — 지금은 화면 터치로 시작.

## 시험

가짜 카메라 · 마이크(Chrome `--use-file-for-fake-video-capture` · `--use-file-for-fake-audio-capture`)로 기본 · 크리스마스 흐름을 끝까지 돌렸다(2026-11-23, 새 화면): 한 사람 약 71초, 귀 마이크 자동 시작 · 끝, 받아쓰기 · 이름(서윤 · 민준), 위로 밀어 넣기, 산타 답장, 휴대폰 연결 · 받는 사람 페이지 모두 동작. 하이드레이션 경고 0. 시험 스크립트는 세션 임시 폴더라 남지 않는다 — 다시 하려면 같은 방법으로.
