# 키오스크 체험 모드 7종 (2026-10-12, 10-13 확장)

네일 · 명함 · 스킨케어 · 캐리커처 · 보이스 · 미래 직업 탐색 · 버추얼 메이크업. 목업(`Kiosk-New-Modes-20261012`)을 실제로 도는 운영 모드로 옮긴 것이다. 향 분석(매장·사주)·컬러·타로와 달리 **기존 화면 셸(기존·레트로·맥)을 쓰지 않고 전용 화면 묶음 하나**(`src/app/kiosk/experience`)로 돈다.

- 고르는 곳: 관리자 설정 → **운영 모드** 탭의 '체험 모드'(`docs/kiosk-admin.md`). 저장하면 관리자 창을 닫는 순간(또는 손님이 없는 첫 화면에서) 새로고침해 그 모드로 갈아탄다. 이 탭은 **운영 모드 = 매장 기본 하나**, 그 밖의 모든 프로그램(사주·컬러·타로 + 아래 일곱 가지)을 **체험 모드**로 묶어 보여 준다. **체험 모드는 고른 그 키오스크에만 적용된다**(2026-10-13, 기기 저장 — `docs/kiosk-modes.md` '기기별 체험 모드'). 매장 기본은 모든 키오스크가 함께 쓴다.
- 미리보기: 주소에 `?mode=studio-nail` 처럼 붙이면 기기 설정을 건드리지 않고 그 모드로 본다(`card`·`skin`·`draw`·`voice`·`career`·`makeup`). 운영 사이트에서 웹브라우저로 열면 먼저 비밀번호를 묻는다(`docs/kiosk-modes.md` '웹브라우저 접속 비밀번호').
- 화면 디자인·글꼴·평소 배경·행사 배경 설정은 이 모드들에서 쓰이지 않는다(관리자 창이 '전용 디자인 사용 중'으로 알린다).
- 발권 번호·기록(`/api/kiosk/record`)은 없다. 결과는 손님이 **휴대폰으로 받기**나 **영수증 출력**을 눌렀을 때만 올라간다(영수증의 QR 이 그 주소다).

## 목업에서 정한 선 — 지킨 것과 바꾼 것

- **스킨케어**는 자가 체크로 루틴을 정리하는 안내다. 사진을 찍지 않고, 질병·피부 나이·수치를 말하지 않는다.
- **직업 탐색**은 관심사가 중심이다. 능력이나 미래를 단정하지 않는다(결과는 '탐색해 볼 직업 예시'). 2026-10-13 에 운영 요청으로 **MBTI 와 관상(재미로 보는 인상 읽기)** 을 더했다 — 목업의 '얼굴로 추정하지 않는다'는 선을 바꾼 것이라, 둘 다 건너뛸 수 있게 하고 점수는 조금만 보태며(질문 하나 2점 · MBTI 글자 0.5~1점 · 관상 특징 1점) 화면과 결과에 '재미로 보는 풀이, 능력·미래를 말해 주지 않는다'고 적는다. 관상 사진은 기기 안에서만 보고 올리지 않으며 피부색·성별·나이는 보지 않는다(얼굴 길이의 비율만).
- **보이스**는 손님 본인의 녹음에 스타일(높낮이·음색·울림)만 입힌다. 다른 사람의 목소리를 흉내 내거나 합성하지 않는다.
- **명함**은 디지털 결과물이다. 명함 프린터·주문·결제가 없다(영수증에는 미리보기와 받는 QR 만 찍힌다).
- **메이크업**의 얼굴형 보정은 픽셀을 조금 옮기는 것이다(가장 세게 해도 얼굴 반 폭의 7%쯤). 머리 '모양'을 바꾸는 것만 생성형이다 — 얼굴·표정·옷·배경은 그대로 두라고 못 박는다.
- 브랜드 이름·로고는 넣지 않았다. 글자·버튼·입력란은 모두 실제 부품이다(목업 이미지에서는 첫 화면 그림·스타일 견본만 잘라 썼다 — `public/assets/kiosk-experiences`).

## 모드별 동작

### 네일 (`nail/engine.ts`)
손 특징점 21개(MediaPipe HandLandmarker, `public/models/hand_landmarker.task`)에서 손가락마다 손톱 자리·방향·크기를 계산하고, 배경과 구분되는 사진에서는 손가락 윤곽을 읽어 폭·끝을 다듬는다. 손톱 모양의 색 층만 올리고 원본의 명암을 다시 곱해 입체를 남긴다. 손 찾기는 같은 사진도 크기·기울기에 따라 놓칠 수 있어, 못 찾으면 줄이거나 ±14° 돌려 다시 본다. 굽은 손가락은 건너뛰고, 손톱이 3개 미만이면 다시 찍게 한다. 자동으로 잡은 크기가 안 맞으면 손님이 '손톱 크기 − +'로 고친다.

**찍기 전 안내와 자동 촬영(2026-10-13)** — 손톱 자리의 오차는 손 크기에 비례해서, 손이 작게 찍히면(손톱 폭 11~25픽셀) 조금만 어긋나도 티가 났다. 그래서 크게·바르게 찍히도록 촬영 단계를 고쳤다:
- 미리보기를 초당 한두 번(기기 속도에 따라) 읽어 한 줄로 알린다: 손 없음 · 손바닥(`손등이 보이게 돌려 주세요`) · 굽은 손가락 · 멀다(손 길이가 화면 높이의 반 미만, `HAND_MIN_SIZE`) · 손끝이 잘림 · 좋음. 안내선(손 모양)은 그 크기의 기준이고, 좋으면 초록으로 바뀐다.
- 좋은 자리에서 0.7초(`AUTO_STEADY_MS`) 멈춰 있으면 알아서 3·2·1 을 세고 찍는다. '손 사진 촬영' 버튼은 그대로 눌러도 된다(안내가 까다로워도 막히지 않게).
- 카메라는 가장 큰 영상(2560×1440 을 바람)으로 받아 긴 변 1600 까지 찍는다(`useKxCamera(…, { sharp: true })`). 기기가 그 영상을 초당 10장도 못 내면 평소 크기(1280×960)로 내린다.
- 윤곽을 못 읽을 때 쓰는 기본 크기를 키웠다(폭 약 8%, 길이는 폭의 1.22 → 1.3배 — 늘어난 길이는 큐티클 쪽으로).

### 메이크업 (`makeup/engine.ts`)
얼굴 특징점 478개(FaceLandmarker, 컬러 모드와 같은 모델)에서 자리를 찾는다. 도구는 여덟: 립 · 블러셔 · 섀도(색 층: 색 + 곱하기) · 눈썹(눈썹 자리에 색) · 아이라인(윗눈꺼풀 선을 따라, 눈꼬리 쪽이 굵게 · 윙 선택) · 속눈썹(짧은 곡선) · 얼굴형(턱선을 안쪽으로, 눈을 조금 크게, 피부결을 고르게 — `beautify`) · 헤어 색(머리카락 분할 모델 16MB, 헤어 탭을 열 때 받는다 — 밝은 색은 먼저 밝힌 뒤 색을 입힌다). 가운데 선을 밀어 원본과 비교한다.

**머리 모양 바꾸기(AI)** — 헤어 탭의 버튼. 처음 찍은 사진을 서버로 보내 머리만 바꾼 사진(단발·긴 웨이브·숏컷·포니테일·시스루 뱅·컬 펌)을 받아, 그 사진을 새 바탕으로 삼아 화장을 다시 올린다(`src/lib/kiosk/hairstyle.ts`). '원래 머리로' 되돌릴 수 있다.

### 보이스 (`voice/audio.ts`)
`MediaRecorder` 로 녹음 → 24kHz 한 채널로 풀어 앞뒤 빈 소리를 자르고 음량을 맞춘다. 필터는 Web Audio 로 기기 안에서 만든다(2026-10-13 에 라디오·로봇·동화를 재미있는 여덟 가지로 바꿨다):

| 필터 | 만드는 법 |
|---|---|
| 다람쥐 | 아홉 반음 위 + 조금 빠르게 |
| 거인 | 여덟 반음 아래 + 저음·동굴 울림(말소리 대역도 함께 세운다 — 작은 스피커에서 웅웅거리지 않게) |
| 외계인 | 네 반음 위 + 빠르게 떨리는 음높이 + 금속성(링 모듈레이션) |
| 유령 | 말보다 울림이 먼저 밀려온다(뒤집어 울린 뒤 다시 뒤집기) + 느린 떨림 + 긴 여운 |
| 합창단 | 한 옥타브 아래·제 음·장3도·5도를 겹치고 홀 울림 |
| 노래방 | 0.2초 메아리 + 울림 |
| 거꾸로 | 끝에서부터 처음으로 |
| 무전기 | 좁은 대역·찌그러짐 + 앞 '치직' · 뒤 '삐빅' |

높낮이는 겹쳐 잇기(WSOLA)로 길이를 지킨 채 바꾼다. 너무 짧거나(1초 미만) 소리가 거의 없으면 다시 녹음하게 한다. 마이크를 못 찾으면 안내를 띄우고 3초마다 다시 본다.

### 캐리커처 (`src/lib/kiosk/caricature.ts`)
프롬프트는 닮음 유지·친절한 톤·글자 금지를 고정으로 두고 스타일·과장 정도만 바꾼다. 2026-10-13 에 고친 것:
- **세 스타일이 한눈에 다르게** — 선화는 색이 전혀 없는 잉크 선, 수채화는 번지는 물감과 뒤의 물감 얼룩, 코믹은 굵은 선·원색·망점과 빛살 바탕. 스타일 견본 그림(`draw-style-*.webp`)도 가상 인물을 실제로 세 스타일로 그린 것으로 바꿨다.
- **머리 모양** — 길이·볼륨·결·가르마·앞머리·묶음·색을 그대로 두라는 문단을 따로 뒀다(앞머리를 만들어 그리던 것).
- **없는 안경 금지** — 안경을 예로 들면 모두에게 씌워 그렸다. 보이는 것만, 없는 것은 더하지 않게 못 박았다.
- **같이 찍기** — 촬영 화면의 '혼자 · 같이'. 같이는 사진을 가로(4:3)로 찍고, 사람 수·왼쪽부터의 순서·저마다의 얼굴과 옷을 지켜 한 장에 그리게 한다(그림도 4:3).

### 명함 (`card/design.ts` · `src/lib/kiosk/card-art.ts`)
손님이 느낌(여덟 가지 중 하나, 또는 직접 적은 말, 둘 다도 된다)을 고르면 서버가 가로 그림 한 장을 그린다 — 글자 없이, 왼쪽 55%는 차분하게, 볼거리는 오른쪽에. 얼굴 사진을 넣으면 오른쪽에 그 사람의 그림을 넣는다. 화면은 그 그림을 9:5 로 잘라 깔고 글자 쪽에 옅은 막을 쳐 이름·직업·연락처를 올린다(바탕 밝기를 보고 글자 색을 정한다 · 글자를 오른쪽에 두면 그림을 뒤집는다). 뒷면은 같은 그림을 흐리게 깐다(한 장만 그려 앞뒤가 한 벌). '명함'이라는 말을 프롬프트에 쓰면 책상 위에 놓인 명함 사진을 그려 와서 쓰지 않고, 그래도 둘레에 여백·띠가 붙어 오면 서버가 잘라 낸다(`trimFrame`). 'AI 없이 기본 디자인으로'를 누르면 예전 템플릿 3 × 색 4 × 정렬로 만든다.

### 생성 API 공통 (`src/lib/kiosk/image-gen.ts`)
OpenRouter 이미지 모델(기본 `google/gemini-2.5-flash-image`, 장당 약 $0.04·9초)로 그린다. 실패하면 `OPENROUTER_IMAGE_MODEL` 로 한 번 더. 사진과 결과는 서버에 남기지 않는다.

| 환경 변수 | 뜻 |
|---|---|
| `OPENROUTER_KIOSK_IMAGE_API_KEY` | 체험 모드 생성 전용 키(비용을 따로 보고 싶을 때). 없으면 `OPENROUTER_API_KEY` |
| `OPENROUTER_KIOSK_IMAGE_MODEL` | 모델 바꾸기(옛 이름 `OPENROUTER_CARICATURE_MODEL` 도 읽는다) |
| `KIOSK_IMAGE_DAILY_LIMIT` | 서버 인스턴스당 하루 생성 상한(기본 400, 세 기능 합쳐서). 분당 8회 제한도 있다 |

### 스킨케어 (`skin/routine.ts`)
규칙 표로 추천 루틴을 만든다(AI 호출 없음). '루틴 직접 고치기'를 누르면 줄마다 위·아래·빼기가 생기고, '단계 추가'로 고를 수 있는 단계(세안·각질 케어·정돈·에센스·마스크팩·아이크림·보습·여유 있는 날 한 단계·자외선 차단)나 직접 적은 이름(12자)을 더한다. 한 번에 7단계까지. 자가 체크의 답을 바꾸면 추천이 달라지므로 고친 것은 버린다.

### 직업 탐색 (`career/data.ts` · `career/face.ts`)
네 축(만들기·문제 풀기·사람 돕기·이야기하기)의 점수로 직업 열여섯 가운데 셋을 고른다(같은 답이면 같은 결과). 관상은 얼굴 특징점에서 여섯 비율(이마·눈·눈과 눈썹 사이·코·입·턱)을 재고, 평균에서 가장 먼 셋을 그 사람의 '눈에 띄는 인상'으로 골라 옛 관상 풀이의 좋은 말만 붙인다. 평균값은 시험 얼굴 여섯으로 잡은 것이라 정밀하지 않다 — 재미가 목적이다.

## 휴대폰으로 받기 (`src/lib/kiosk/share.ts`, `share-store.ts`)

`POST /api/kiosk/share` → 토큰(생성 시각 8자 + 무작위 20자) → QR → `/kiosk/get/[token]`. 파일은 한 번에 4개·합계 3MB 까지(JPG·PNG·WAV·PDF), 머리 바이트로 형식을 확인한다. 24시간이 지나면 페이지·파일 주소를 막고, 파일은 다음 업로드 때 지운다.

**저장소 버킷(`analysis-images`)은 그림 형식만 받는다.** 그림은 그대로 올리고, 그 밖의 것(WAV·PDF·파일 목록)은 1×1 PNG 의 사설 청크(`kxDt`)에 담아 `이름.png` 로 올린다(`my-voice.wav.png`, `meta.json.png`). 내려줄 때 청크를 풀어 원래 형식으로 준다. 버킷 설정을 바꿀 필요가 없다.

## 배포 전에 · 운영 메모

- 서버 환경 변수는 기존 것만으로 돈다(`KIOSK_ENABLED`·`KIOSK_ALLOW_REMOTE`, `OPENROUTER_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`).
- **보이스**: 매장 키오스크(Windows POS)는 웹캠(ABKO APC930) 내장 마이크가 잡혀 있고, 셸이 `media` 권한(카메라·마이크)을 허용한다(2026-10-12 원격 확인). **스피커가 실제로 소리를 내는지는 매장에서 확인**해야 한다 — 출력 장치는 '헤드폰(High Definition Audio)' 하나만 잡힌다.
- **네일·메이크업**: 인식 엔진(WASM 약 9MB)과 모델(손 7.8MB · 얼굴 3.8MB)은 손님이 없는 첫 화면에서 조각으로 받아 기기 보관함에 둔다. 모드를 처음 켠 직후 첫 손님은 촬영 뒤 준비에 시간이 더 걸릴 수 있다.
- **캐리커처 · 명함 · 메이크업의 머리 모양 바꾸기**는 누를 때마다 비용이 든다. 행사에서 오래 켜 둘 때는 OpenRouter 사용량을 본다.
- 키오스크 앱은 자동으로 새로고침하지 않는다 — 배포 뒤 앱을 다시 켜야 새 화면이 뜬다.

## 한계

- 네일은 손톱을 '찾는' 것이 아니라 손가락 뼈대에서 '계산'한다. 뼈대의 오차(손 크기의 1~2%)와 사람마다 다른 손톱 폭(±20%)은 남는다 — 촬영 안내로 크게 찍게 해 줄였지만, 손톱 가장자리까지 정확히 맞추려면 손톱 영역을 직접 찾는 전용 모델이 필요하다(손끝을 잘라 넣는 작은 분할 모델 — 학습 데이터 필요). 살색 배경(얼굴 앞)에서는 윤곽 다듬기가 거의 안 된다. 엄지는 옆으로 돌아 있어 가장 덜 맞는다.
- 색으로 손톱과 살을 가르는 방법, 서버 비전 모델에게 손톱 위치를 묻는 방법은 시험했으나 들쭉날쭉해서 쓰지 않았다(2026-10-13: 앞의 것은 밝은 피부에서 폭을 25% 작게 잡았고, 뒤의 것은 어두운 피부에서 손가락 전체를 손톱으로 잡았다).
- 보이스의 '로봇'은 링 모듈레이션이라 말소리가 다소 알아듣기 어려워진다(의도한 효과).
- 생성 상한(분당·하루)은 서버 인스턴스 안에서만 센다 — 인스턴스가 여럿이면 느슨하다.
- 생성 결과는 매번 조금씩 다르다. 선화에 색이 섞이거나 명함 바탕에 여백이 붙는 일을 프롬프트와 후처리로 줄였지만 아주 없애지는 못한다.
- 헤어 색은 머리카락 자리에 색을 입히는 것이라 검은 머리의 금발은 실제 탈색처럼 보이지 않는다(밝힌 갈색에 가깝다). 머리 모양 바꾸기는 사진이 새로 그려져 원본과 구도가 조금 달라질 수 있다.
- 영수증의 그림은 감열지 점묘(1비트)다 — 캐리커처 선화가 가장 잘 나오고, 사진 같은 명함 바탕은 거칠게 나온다. 실제 프린터로는 아직 찍어 보지 않았다.
- 체험 모드에는 행사 배경·글꼴이 적용되지 않는다.
