# 키오스크 운영 모드 (매장 ↔ 행사)

같은 키오스크 프로그램으로 매장 상시 운영과 외부 행사를 오간다. 모드마다 **켜는 분석 프로그램, 첫 화면 문구(5개 언어), 화면 제목줄, 영수증 머리말·행사 줄**이 다르다.

- 바꾸는 곳: 키오스크 우측 상단 모서리(언어 버튼 위, 2026-10-09 에 우측 하단에서 옮김) → 비밀번호 → STORE ADMIN 맨 위 **운영 모드**. 같은 종류의 키오스크(행사장 2대 포함)가 모두 다음 손님부터 따라간다.
- 저장: 기기 설정 `settings-kiosk` 의 `mode`(없으면 매장 기본). 포토부스는 따로 — 아래 '포토부스 운영 모드'.
- 목록: `src/lib/kiosk/modes.ts` — 행사가 생기면 항목 하나를 더한다(`id`, 관리자 표시 이름·설명, 제목줄 이름, `programs`, 언어별 `attract`, `receipt`).

## 매장 이벤트와의 관계

모드마다 `storeEvents` 가 있다. 매장(`wow`)만 켜져 있어 와우 생카 이벤트 배경·글꼴(docs/screen-events.md)이 기간 중·수동 적용으로 우선한다. 행사 모드(`kwave-2026`)에서는 매장 이벤트를 무시하고 기기에서 고른 배경·글꼴을 그대로 쓴다.

매장 모드에서 이벤트 글꼴이 우선 적용 중이면 STORE ADMIN 글꼴 칸에 안내가 뜬다(고른 글꼴은 저장되고, 이벤트가 끝나거나 해제되면 보인다).

## 모드

| id | 이름 | 프로그램 | 영수증 |
|---|---|---|---|
| `wow` (기본) | AC'SCENT WOW 매장 | 최애 이미지 분석 | WOW · SCENT REPORT, 향 먼저 |
| `kwave-2026` | K-WAVE 댄스 페스티벌 (2026.10.3~10.4, 이태원로 세계문화마을) | 사주 분석 | 사주 향 처방전 — 명식 먼저 |
| `ai-color` | AI 퍼스널 컬러 — 행사·팝업용 | AI 퍼스널 컬러 진단(고르기 화면 없이 바로) | 진단서만 — 향·레시피·발권 번호 없음 |
| `ai-tarot` | AI 타로 — 행사·팝업용 | AI 타로(고르기 화면 없이 바로) | 타로 리딩만 — 향·레시피·발권 번호 없음 |

`programs` 에 둘 이상을 넣으면 첫 화면 다음에 프로그램 고르기 화면이 나온다(예: 사주 + 내 이미지 분석).

**영수증 출력(모든 모드, 2026-10-09)**: 프린터가 있는 기기에서 결과 화면의 '영수증 출력'을 누르면 미리보기가 열리면서 바로 인쇄가 시작된다(미리보기에서 '인쇄하기'를 한 번 더 누르지 않는다). 한 장 뽑은 뒤에는 결과 버튼이 '영수증 미리보기'로 바뀌어 다시 눌러도 자동 인쇄하지 않고, 더 뽑을 때는 미리보기의 '한 장 더 출력'(같은 발권 번호). 연타해도 한 번만 인쇄한다. 인쇄가 실패하면 버튼은 '영수증 출력'으로 남아 다시 누르면 다시 시도한다. 프린터가 없는 웹에서는 예전처럼 미리보기 → 'PNG 저장'.

## 사주 영수증(처방전) 순서

`renderKioskReceipt(data, { brand: { theme: 'saju', subtitle, eventLines } })`

1. AC'SCENT · 부제(SAJU SCENT · 四柱香 處方) · **四柱香 處方箋 / 사주 향 처방전**(두 줄 괘선 사이)
2. 발권 정보
3. 명식(네 기둥 한자) · 일간 · 용신 · 생시 → 오행 분포(용신 ◀)
4. **處方 香 · 처방 향** — 향 번호·이름·노트
5. 처방의 연유 · 단계별 향 · 쓰는 법 → 레시피
6. 꼬리말 + 행사 줄(2026 K-WAVE DANCE FESTIVAL / 세계문화마을 · 이태원로 · 10.3~10.4) → 주의사항 → 맨 아래 안내

K-WAVE 모드 전용: 제조 레시피를 **굵은 상자**로 감싸고(`recipeBox`), 맨 아래 안내를 '이 영수증을 직원에게 보여주세요. / 적힌 레시피 그대로 조향을 하시면 됩니다.'로 바꾼다(`counterNotice`, 5개 언어).

## 첫 화면 제목 — 홍보 배너 모양 (`poster`)

모드에 `poster` 가 있으면 첫 화면의 티켓·워드마크·부제 자리를 홍보 배너와 같은 제목으로 바꾼다(`src/app/kiosk/PosterTitle.tsx`, 기존·레트로·맥 공통). K-WAVE: **SAJ**U!(U! 벽돌색) / 사주로 찾는 나만의 향, / AI 조향사(벽돌색) / A I P E R F U M E R / 가는 선 / 지원 언어 줄.

- 외국어 화면은 둘째 줄을 그 언어의 `attract.sub` 로 바꾸고 제목 전체를 조금 줄인다(아래 카드 문장이 길어 시작 버튼이 밀려나지 않게).
- 레트로·맥은 흰 창 안이라 배너 고정색(먹·벽돌), 기존(클래식)은 배경 그림 위라 배경의 글자색·강조색을 쓴다 — 노랑 배경 '흥겨운 오행 춤'(kiosk-saju-10)에서 배너와 같은 색이 된다.
- 포토부스의 짝: `src/components/photobooth/IdolPosterTitle.tsx`(IDOL! / AI 포토부스).

## 결과 한 장 스크롤 (`resultOnePage`)

모드에 `resultOnePage: true` 면 사주 결과 4장(명식·풀이·물음·처방)을 장 넘기기 없이 한 화면에 이어 붙여 스크롤한다(`SajuOnePageView`, SajuReport.tsx). 장 이름은 짙은 띠 제목으로 남고, 아래 버튼은 '처음으로'·'영수증 인쇄' 둘. 손님이 몰리는 행사장에서 장 넘기느라 줄이 길어지지 않게 K-WAVE 에서만 켰다. 매장 모드는 예전처럼 4장.

## 모드 기본 배경

`defaultBackground` 가 있으면 STORE ADMIN 에서 그 모드를 고를 때 키오스크 배경도 함께 바뀐다. K-WAVE 는 `kiosk-event-kwave-2026`(기본 배경 목록의 '행사' 배경, `catalog.json`). 매장 모드로 돌아갈 때는 배경이 자동으로 돌아가지 않으니 화면 배경에서 다시 고른다.

흑백 감열지용이라 색 대신 괘선·한자 제목·◀ 표시로 구분한다.

## 사주 흐름 언어·결과 화면

- 입력 단계(목적·생년월일·시간·궁합 상대·고민), 분석 대기 문구, 결과 4장, 영수증 사주 제목은 `src/lib/kiosk/saju-i18n.ts` 에서 5개 언어로 나온다.
- AI 해석 문장은 화면 언어로 받는다 — `/api/kiosk/analyze/saju` 에 `locale`(ko·en·ja·zh·zh-Hant, 번체는 zh 지시 + 번체 지시). 향 이름·키워드도 그 언어로 온다.
- 만세력 값(오행 '목', 신강, 띠)은 서버가 한국어로 주므로 화면·영수증에서 사전으로 바꾼다(`saju-receipt.ts`).
- 결과 화면은 `src/app/kiosk/SajuReport.tsx` — 오행 색 기둥 타일·오행 막대·용신 카드·기운 카드·핵심 세 가지·향 층 카드. 긴 해석은 앞 1~2문장만 보이고 '자세히 보기'. 흰 카드 + 짙은 글자(어떤 배경에서도 읽힘), 본문 22px·제목 26~50px.
- 한자는 Noto Sans TC(키오스크에 실린 번체 글꼴)로 통일 — 화면 글꼴 55종에는 한자가 없다.

## 사주 프로그램 배경과 추천 글꼴

- 사주 전용 배경 11종(`collection: 'saju'`, `kiosk-saju-01`~`11`)을 기본 배경 목록에 넣었다. 이름·색·추천 글꼴은 배경 그림을 이미지 AI로 분석해 정했다(예: 연분홍 수묵화 → 고운돋움, 네온 필묵 댄스 → 검은고딕, 오행의 춤 → 나눔스퀘어라운드). K-WAVE 기본 배경의 추천 글꼴은 프리텐다드.
- 배경마다 `font`(추천 글꼴) — **배경을 화면에 적용하면 기기 글꼴도 그 글꼴로 바뀐다**(서버 `selectSharedBackground`, 기기 STORE ADMIN·관리자 웹·운영 모드 전환 공통). 그 뒤 STORE ADMIN 글꼴 칸에서 다시 바꿀 수 있고, 다음에 배경을 바꿀 때까지 유지된다. 추천 글꼴이 없는 배경은 글꼴을 건드리지 않는다.
- 관리자 웹 배경 편집 창에서 추천 글꼴을 바꾸거나 없앨 수 있다. STORE ADMIN 배경 목록은 추천 글꼴 이름과 그 글꼴로 된 미리보기를 보여준다.

## AI 퍼스널 컬러 · AI 타로 (2026-10-08, 10-09 향 제거)

운영 모드가 프로그램을 켜고, 전용 API가 해석을 만들고, 결과·영수증은 기존·레트로 두 화면이 같이 쓰는 부품으로 그린다. **코드가 정하는 것과 AI가 쓰는 것을 나눈다**: 팔레트·뽑힌 카드는 코드, 관찰·풀이 문장은 AI.

**두 프로그램은 향을 추천하지 않는다(2026-10-09).** 제품 고르기 단계, 향 카드, 레시피, 제품 주의사항, 카운터 제출 안내, 발권 번호가 없다 — 결과는 진단서 / 타로 리딩뿐이고 영수증도 그것만 찍는다. 결과 타입(`ColorAnalysisResult` · `TarotAnalysisResult`)은 `ImageAnalysisResult` 를 잇지 않는다. 화면 코드에서는 `scentResultOf(result)` 가 null 이면 향·레시피 관련 일을 건너뛴다.

- **모드 두 개(2026-10-09)**: `ai-color`(퍼스널 컬러만) · `ai-tarot`(타로만). 예전의 `ai-lab`(둘 중 고르기)은 없앴다 — 손님이 고르는 화면 없이 그 모드의 프로그램이 바로 시작된다. 기기 설정에 `ai-lab` 이 남아 있으면 `ai-color` 로 읽는다(`LEGACY_KIOSK_MODE_IDS`).
- **미리보기**: `/kiosk?mode=ai-color` · `/kiosk?mode=ai-tarot` (데모 문구는 `&mock=1`). 기기 설정을 건드리지 않고 그 모드로 열린다 — STORE ADMIN 운영 모드는 모든 키오스크가 따라가므로 시험할 때는 이 주소를 쓴다. 없는 모드 이름이면 무시하고 기기 설정을 따른다.
- **다른 모드에 넣기**: `modes.ts` 의 `programs` 에 둘 이상을 넣으면 그 모드에서는 고르기 화면이 나온다(예: 매장 `['idol', 'color']`). 지금은 어느 모드도 그렇게 쓰지 않는다.
- **문구**: `src/lib/kiosk/program-i18n.ts` — 고르기 화면 + 두 프로그램, 5개 언어. 타로 카드 이름은 `tarot-deck.ts`.
- **AI 호출**(`program-core.ts` `generateParsed`): 최대 3번·전체 88초(키오스크는 110초 대기). 응답이 규칙에 어긋나면 이유를 붙여 다시, 업스트림 오류·잘림이면 같은 프롬프트로 다시. 외국어 결과에 한글이 섞이면 그 문장만 짧은 호출로 고친다(사주와 같은 방식). 로그 검색어 `[KIOSK-COLOR-` · `[KIOSK-TAROT-` + `시도 N 실패`.

### 프로그램 전용 디자인 (2026-10-09)

승인한 두 번째 시안을 기준으로 운영 모드에 따라 전용 디자인이 자동 적용된다. 기존·레트로·맥 화면에서 동일하게 동작한다.

- **퍼스널 컬러 — Chromatic Archive**: 크림색 종이, 남색 타이포, 종이 색상 견본 원화. 결과는 고른 색을 사진 속 상의에만 입혀 보여 주고(아래 '옷 색 미리보기'), 옷을 찾지 못하면 사진 둘레에 색을 댄다. 추천색 8개·피할 색 4개를 누를 수 있다. 사진 전체에는 필터나 색 혼합을 적용하지 않는다.
- **타로 — Moonlit Garden**: 식물 문양의 종이 배경, 세이지색 카드 뒷면, 보라색 선택 카드와 버튼. 22장 중 3장을 선택·취소·펼치는 기존 흐름을 유지한다. 카드 앞면의 의미·이름은 기존 덱 데이터를 사용한다.
- **설정 우선순위**: `ai-color` / `ai-tarot`에서만 전용 배경·글꼴·버튼이 공통 화면 설정보다 우선한다. 저장된 화면·배경 설정은 바꾸지 않으며, 다른 운영 모드로 전환하면 다시 적용된다. STORE ADMIN 운영 모드 영역에 이 규칙을 표시한다.

### 목업 화면 적용 (2026-10-09 · C01–C19 · T01–T20 · M01–M04)

- **공통 화면 부품**: `ProgramScreens.tsx` + `program-screens.css` — 머리띠(브랜드·언어 메뉴·단계 표시), 고객 정보, 퍼스널 컬러 촬영·QR·사진 확인, 분석 대기, 분석 오류, 무입력 안내, 영수증 미리보기. 기존·레트로·맥 셸이 같은 부품을 쓴다(셸은 상태만 넘긴다). 터치 키보드는 셸마다 달라 ReactNode 로 받는다. 문구는 `program-ui-i18n.ts`(5개 언어).
- **목업 그림을 배경으로 깔지 않는다**: 글·입력·버튼·QR·팔레트·결과는 모두 실제 요소다. 이미지는 장식(색 견본 부채, 정원 배경)과 카드 원화뿐이다. 목업 속 키보드 글자·오탈자는 옮기지 않고 기존 `OnScreenKeyboard` 를 쓴다.
- **옷 색 미리보기(C18 · C19)**: `garment-recolor.ts` — MediaPipe ImageSegmenter `selfie_multiclass_256x256`(Apache-2.0, 포토부스와 같은 `public/models` · `public/mediapipe/wasm` 자체 호스팅)의 옷 클래스(4)만 마스크로 쓴다. 사진 한 장당 마스크를 한 번 만들고(결과 화면에서 시작, 40초 제한), 색마다 Lab 공간에서 밝기 차(주름·그림자)는 살리고 색도만 바꾼 **옷만 담긴 투명 PNG** 를 원본 위에 겹친다 — 얼굴·피부·머리·손·배경 픽셀은 원본 그대로다. 색을 누를 때마다 생성 API 를 부르지 않는다(색당 35~60ms, 한 번 만든 색은 캐시). 진단 요청에는 원본 사진만 간다.
  - 마스크: 256² 확률 → 양선형 확대 → smoothstep → 원본 밝기로 guided filter(경계) → 큰 덩어리만 남기기(배경 점 제거). 옷 면적이 3.5% 미만이면 `no-garment`.
  - 실패·없음: 엔진 준비·추론이 40초를 넘기거나 오류면 `failed` → 얼굴 둘레 드레이프로 돌아가고 '다시 시도' 버튼. 상의가 화면에 거의 없으면(얼굴만 크게) `no-garment` → 드레이프 + 안내. 모델 파일을 아직 다 받지 못했으면 `unavailable` → 안내 없이 드레이프.
  - 정리: 다시 찍기 · 처음으로 · 무입력 초기화 · 얼굴 없음에서 `releaseGarment()` — blob 주소를 풀고 세대 번호를 올려 진행 중인 작업 결과를 버린다.
  - **파일 받기는 손님이 없을 때만(2026-10-09 실기 장애 뒤)**: 모델(16MB)·엔진 WASM(9.5MB, 전송 약 3MB)은 퍼스널 컬러 첫 화면에서 2.5초 뒤부터 받고, 손님이 시작하면(첫 화면을 떠나면) 받던 것을 멈춘다(`pauseGarmentDownload`). 다 받은 파일은 메모리(blob)에 두고 그것만 쓴다 — 손님 진행 중에는 이 기능 때문에 망을 쓰지 않는다. 진단 중에는 옷 계산을 시작하지 않는다.
    - 왜: 매장 망이 느리다(실측 45~140KB/s). 처음 배포 때는 진단 요청과 같은 순간에 모델 16MB 를 받기 시작해, 서버는 4.8초 만에 답했는데 키오스크가 결과 화면에 가지 못했다(그 진단 뒤 기록 요청이 없음, 키오스크 ping 3~4초·손실). 첫 손님이 오기 전 첫 화면에서 다 받지 못하면 그 손님은 드레이프를 본다.
  - **계산은 웹 워커에서**(`garment.worker.ts`, 순수 계산은 `garment-core.ts`): 추론·마스크 다듬기·색 칠하기·PNG 만들기를 화면 스레드 밖에서 한다. 엔진은 CPU(XNNPACK)만 — 오래된 GPU 의 WebGL 준비가 멈추는 위험을 피한다. 제한 시간을 넘기면 워커째 끝내고 다음 사진에서 새로 만든다. 번들러(Turbopack)는 이 워커를 일반(classic) 워커로 만든다 — 모듈 워커가 되면 MediaPipe 로더용 `importScripts` 대체품이 대신 쓰인다.
  - 한계: 목걸이·가방끈처럼 옷 위에 걸친 것도 옷으로 칠해질 수 있다. 겉옷과 안에 입은 옷을 구분하지 않고 둘 다 칠한다. 아주 어두운 색을 고르면 경계에 옅은 테가 남을 수 있다. 머리 근처의 흐린 배경이 드물게 섞인다.
- **촬영 안내**: 얼굴 타원 + 어깨선 가이드, 세 번째 안내는 '어깨와 상의까지'. 결과 사진은 3:4 그대로(위를 기준으로 자르지 않는다) — 상의가 보이게.
- **폰 업로드(M01–M04)**: 퍼스널 컬러 세션의 QR 주소에 `&p=color` 가 붙으면 `KioskUploadClient` 가 Chromatic Archive 화면(`upload-color.css`)을 쓴다. 다른 프로그램(최애 분석 등)의 업로드 화면은 그대로다.
- **타로**: 덱·선택 데이터는 그대로이고 화면만 목업에 맞췄다(질문 아래 안내, 펼친 뒤 한 줄, 큰 '풀이 보기', 결과의 세 장 흐름 줄). 결과 카드는 손님이 실제로 뽑은 카드이며 정/역방향도 그대로다.
- **검증**: 시험 응답으로 확인했다 — 분석은 고정 JSON(컬러) 또는 서버 데모 응답(타로, 실제로 뽑은 카드), `/api/kiosk/record` 는 가로채 가짜 성공. 스크린샷과 목업 비교는 `design-review/kiosk-mockup-impl-20261009/`(git 제외).

### AI 퍼스널 컬러 진단 (`color`)

- **흐름**: 이름·성별 → 촬영(키오스크 카메라가 먼저, 안내 3줄 · 폰 QR 업로드 가능) → 사진 확인 → 진단(6~10초) → 결과 한 장 스크롤 → 영수증(진단서).
- **진단**: `POST /api/kiosk/analyze/color` — 사진 한 장으로 8유형(봄 라이트·브라이트 / 여름 라이트·뮤트 / 가을 뮤트·딥 / 겨울 브라이트·딥) 중 하나, 네 축 눈금(온도·명도·선명도·대비), 관찰(피부·머리카락·눈동자), 스타일 가이드. 프롬프트·검증은 `color-analysis.ts`.
- **얼굴 없음**: `NO_FACE` → 사진을 물리고 촬영 화면으로. 안내는 다시 찍을 때까지 촬영 화면에 남는다. 분석 실패 카드에는 '다시 찍기'가 있다(같은 사진으로 다시 보내면 또 실패하기 쉽다).
- **확신도**: 읽을 수 없으면 '보통'. '낮음'이면 결과에 조명 안내가 뜬다.
- **팔레트**: 유형별 고정값(`color-types.ts`, 잘 받는 색 8 · 피할 색 4). AI는 그 색에 손님 언어로 이름만 붙인다.
- **결과 화면**(`ColorReport.tsx`): 유형·웜/쿨 → 옷 색 미리보기(원본 보기 · 원본과 나란히 비교) → 추천 8색 · 피할 4색 → 톤 분석 → 스타일 가이드. 옷을 찾지 못하면 얼굴 사진 둘레에 색을 대어 보는 드레이프로 대신한다.
- **사진**: AI 서버로만 간다. 기록(`/api/kiosk/record`)·영수증에 넣지 않고, **기기 아카이브(`kiosk.saveResult`)에도 넘기지 않는다** — 셸은 받은 사진을 `output/<시각>/photo.jpg` 로 남기기 때문이다.

### AI 타로 (`tarot`)

- **흐름**: 이름·성별 → 주제(오늘의 흐름·연애·일·금전·나 자신) → 질문 한 줄(선택) → 카드 세 장 뽑기 → 펼치기 → 풀이(6~10초) → 결과 한 장 스크롤 → 영수증(리딩).
- **카드**: 메이저 아르카나 22장(`tarot-deck.ts`). 화면에서 섞고(역방향 30%) 손님이 뒷면을 보고 고른다 — 고른 순서대로 과거·현재·미래. 서버는 받은 세 장을 검증만 한다.
- **고르기**: 고른 카드(또는 채워진 자리)를 다시 누르면 그 한 장만 취소된다. '다시 섞기'는 펼치기 전에만 — **펼친 뒤에는 다시 뽑을 수 없다**(앞면을 보고 마음에 들 때까지 뽑는 것을 막는다).
- **카드 그림**: 문라이트 가든에서는 [NEANDER 타로 데모](https://neander-ai-tarot.vercel.app/)의 메이저 아르카나 원화 22장을 로컬 WebP로 표시한다(`TarotCard.tsx`, `tarot-card-art.css`). 카드 ID 0–21과 기존 다국어 이름·정/역방향을 그대로 연결하며 역방향은 앞면 전체를 180° 돌린다. 이미지 로드 실패 시 숫자·원소 기호·이름 카드로 대체한다. 프롬프트는 검증하지 않은 그림 세부 묘사 대신 카드의 의미를 설명한다.
- **데모에서 참고한 동작**: 두 더미로 섞기(900ms) → 세 더미로 나누어 모으기(600ms) → 부채꼴로 순차 배치(900ms 후 선택 활성화). 선택한 뒷면은 과거·현재·미래 자리로 이동하고, 세 장은 순차적으로 뒤집힌다. 펼치기 완료 전에는 풀이 버튼을 잠근다. 모션 감소 설정에서는 대기 없이 선택할 수 있다. 타이머는 화면을 나가면 해제된다.
- **배치**: 데모의 촘촘한 78장·1장 뽑기는 가져오지 않았다. 기존 22장·3장 선택을 유지하면서 세 줄의 완만한 부채꼴(기본 8+8+6)로 배치한다. 좁은 화면에서는 열을 줄이고 세로로 스크롤하여 카드별 터치 영역을 확보한다. 모션 구현은 `TarotSteps.tsx`, `tarot-motion.css`, `TarotShuffleAnimation.tsx`, `tarot-shuffle.css`.
- **풀이**: `POST /api/kiosk/analyze/tarot`(`tarot-analysis.ts`) — 카드별 풀이·세 장의 흐름·조언 3개. 카드 이름은 손님 언어 이름을 프롬프트에 그대로 준다(화면과 같은 이름). 단정적 예언, 불행 예고, 의학·법률·투자 조언, 향 이야기는 프롬프트에서 막는다.

### 영수증

`ReceiptData.color` / `.tarot` 가 있으면 진단서(유형·눈금·색 이름·스타일) 또는 타로 리딩(카드 세 장 그림·자리별 한 줄·흐름·조언)만 찍는다. PRODUCT 줄·향·레시피·PRECAUTION·카운터 안내·TICKET 이 빠져 길이가 절반쯤이다(약 1,300px). 머리말은 `PERSONAL COLOR REPORT` / `TAROT READING`. 만드는 곳은 `extra-receipt.ts`.

포토부스(`/booth`)도 같은 방식으로 매장 ↔ 행사를 오간다. 사주 테마가 아니라, K-POP 행사에 맞춰 **K-POP 무대 메이크업** 콘텐츠를 쓴다.

- 바꾸는 곳: 포토부스 우측 하단 → 비밀번호 → STORE ADMIN 왼쪽 칸 맨 위 **운영 모드**. 같은 종류의 포토부스가 모두 다음 손님부터 따라간다.
- 저장: 기기 설정 `settings-booth` 의 `mode`(없으면 매장 기본). 키오스크 `settings-kiosk` 와 따로 — 한쪽을 바꿔도 다른 쪽은 그대로.
- 목록: `src/lib/booth/modes.ts` — `id`, 관리자 이름·설명, 제목줄 브랜드 줄(`brandLine`), 대기 화면 문구(`attract`), 무대 메이크업(`stageMakeup.eventLines`), 기본 배경(`defaultBackground`), `storeEvents`.

|---|---|---|---|
| `wow` (기본) | AC'SCENT WOW 매장 | 지금 그대로(최애·포토카드·같이 찍기·일반 촬영) | 바꾸지 않음 |
| `kwave-2026` | K-WAVE 댄스 페스티벌 (2026.10.3~10.4, 이태원로 세계문화마을) | 첫 화면 **무대 메이크업 룩** 고르기 → 바로 촬영(촬영 방식 타일 없음) + 인화물 하단 '오늘의 무대 메이크업'·행사 줄 | `booth-event-kwave-2026` (가로, 키오스크 K-WAVE 배경의 남보라 색 + 무대 조명·메이크업 소품, 추천 글꼴 프리텐다드) |

### AI 아이돌 컨셉 사진 (K-WAVE 모드)

- **흐름**: 첫 화면에서 컨셉 4개 중 하나를 고른다 — 음방 엔딩요정 · 앨범 재킷 · 무대 직캠 · 뮤비 스틸(`src/lib/booth/idol-concepts.ts`). 동의 문구(사진이 AI 서비스(Google)로 가고 저장하지 않음) 아래 **동의하고 아이돌 되기** / **메이크업만** 두 버튼. 동의 → 이용권 → 한 컷 촬영(실시간 화면에는 컨셉 짝 메이크업 미리보기) → 편집 화면에서 자동으로 생성(20~40초, 진행 막대) → 인화.
- **생성**: 찍은 사람의 얼굴(얼굴형·눈매·피부색·인종·나이)은 그대로 두고 헤어·무대 메이크업·의상·조명·배경만 컨셉대로 새로 만든다. 프롬프트는 `buildIdolPrompt` — 얼굴 고정을 맨 앞에, 피부 밝히기·눈매 바꾸기 금지(외국인 손님), 실존 연예인 닮게·글자·로고·그룹명·노출 의상 금지.
- **인화물**: ON STAGE(AI 사진, 사진 칸 전체) + 왼쪽 아래 BEFORE(실물) 폴라로이드, 하단 띠 `TODAY'S IDOL CONCEPT · 오늘의 아이돌 컨셉` + 컨셉 이름·설명 + 행사 줄. 편집 화면에서 **다시 만들기**(이용권 하나당 생성 3번까지).
- **대신하기**: 키가 없거나, 생성 실패, '메이크업만', 얼굴 0명·4명 이상(3명까지만 생성)이면 아래 얼굴 인식 메이크업 사진으로 만든다(편집 화면에 이유 안내). 메이크업만은 1컷/네컷을 고를 수 있다.
- **서버**: `POST /api/photobooth/idol`(`src/lib/booth/idol-generate.ts`) — 이용권 확인(`/api/photobooth/pass`) 때 받은 서명 표(15분, 3회)가 있어야 생성한다. 손님 사진은 저장·기록하지 않는다. `sharp` 로 JPEG(긴 변 1800)로 줄여 돌려준다.
- **설정(Vercel 환경변수)**: `OPENROUTER_ITAEWONPHOTOBOOTH_API_KEY`(전용 키, 옛 이름 `OPENROUTER_PHOTOBOOTH_API_KEY` 도 읽음 — 없으면 부스는 '메이크업만' 화면으로 자동 전환, `/api/photobooth/config` 의 `idolStage`), 선택 `OPENROUTER_PHOTOBOOTH_MODEL`(기본 `google/gemini-3-pro-image-preview`). 키를 넣고 재배포하면 다음 손님부터 켜진다.

### K-POP 무대 메이크업 (K-WAVE 모드)

- **흐름**: 첫 화면에 촬영 방식 타일(포토카드·최애와·같이·일반)이 없다. 첫 화면에서 바로 룩을 고르고 **촬영 시작** → 이용권 → 촬영(1컷/네컷, 고른 룩의 색이 실시간 화면에 미리 입혀짐) → 편집 → 인화. 매장 모드 첫 화면은 그대로 네 타일.
- 편집 화면 오른쪽 맨 위 **무대 메이크업 · STAGE MAKEUP** 에서도 룩을 다시 고를 수 있다(첫 화면에서 고른 룩이 이어진다). 원본 + 5종(`src/lib/booth/stage-makeup.ts`): 글리터 스테이지 아이 · 블러셔 라인 · 체리 스테이지 립 · 글래스 스킨 글로우 · 네온 그래픽 라이너. 이름·설명은 한국어와 영어를 함께 쓴다(부스 화면은 한국어 전용이라 외국인 손님용으로 영어를 곁들임).
- **얼굴 인식 메이크업**(`src/lib/booth/face-makeup.ts`): MediaPipe Face Landmarker(478 특징점, 모델 `public/models/face_landmarker.task` · wasm `public/mediapipe/wasm` 자체 호스팅 — 행사장 인터넷이 약해도 동작)로 이목구비를 찾아 룩마다 립(색·윤기)·눈두덩 섀도(+펄 글리터)·아이라인(꼬리·네온 빛 번짐·아랫라인)·볼 블러셔(+볼·콧등 블러셔 라인)·하이라이터·피부결 정돈을 실제 얼굴 모양대로 입힌다. 곱하기·soft-light 합성과 가장자리 번짐으로 피부결을 살린다. 룩별 값은 `stage-makeup.ts` 의 `makeup`.
  - 촬영 화면: 카메라 화면 위에 같은 크기로 겹쳐 실시간으로 입혀 보여준다(`LiveFaceMakeup`, 느리면 해상도를 낮춤).
  - 편집·인화: 찍은 원본(긴 변 1800)에 다시 입힌다. 여럿이 멀리 선 컷도 잡히게 사진을 겹치는 조각으로 나눠 얼굴을 찾는다(최대 6명/컷). 같은 사진·룩은 캐시 — 룩을 바꾸면 곧바로(수십 ms) 바뀐다. 첫 화면에서 모델을 미리 불러 둔다.
  - 얼굴을 못 찾거나 모델을 못 불러오면 원본 + 색 보정만(편집 화면에 '얼굴을 찾지 못해…' 안내). 부스는 멈추지 않는다.
- 룩마다 가벼운 **사진 색 보정**(밝기·대비·채도 + 색 덧입히기 + 빛 번짐 + 가장자리 어둡게), **스티커**(반짝이·별·하트·입술·물방울·네온 선, 사진 가장자리 띠에만, 얼굴 자리는 비켜 감), **하단 띠 색**이 다르다.
- 인화물: 사진은 하단 띠 위까지(1200×1546), 하단 띠(x36·y1564·1128×200, 기존 이벤트 푸터·프레임의 비운 자리와 같은 자리)에 왼쪽 `TODAY'S STAGE MAKEUP · 오늘의 무대 메이크업` + 룩 이름(한·영) + 설명(한·영), 오른쪽 행사 줄(`2026 K-WAVE / DANCE FESTIVAL`, `세계문화마을 · 이태원로 · 10.3~10.4`). 룩을 안 고르면 '무대 메이크업 포토부스' 안내 문구.
- 한 컷·네 컷·같이 찍기·포토카드·최애와 찍기 모두 같은 규칙(최애와 찍기는 원래 하단 띠 자리를 무대 메이크업 띠로 바꾼다). 인쇄·사진 QR 저장은 같은 합성 캔버스를 쓰므로 그대로 동작한다.
- 행사 모드는 프레임 없이 시작한다(스티커·하단 띠와 겹치지 않게). 손님이 프레임을 골라 올릴 수는 있고, 스티커는 프레임 위에 붙는다.
- 행사 모드는 `storeEvents: false` — 와우 생카(화면 이벤트) 배경·글꼴을 무시하고, **생카에 묶인 프레임도 목록에서 뺀다**.
- 대기 화면·제목줄: `AC'SCENT × K-WAVE` / `STAGE MAKEUP PHOTO` / `2026 K-WAVE DANCE FESTIVAL` / '오늘의 무대 메이크업, 한 장에' + 'Pick your K-POP stage makeup look'.

### 되돌리기

STORE ADMIN 운영 모드에서 **AC'SCENT WOW 매장**을 누르면 `mode` 가 지워지고 모든 화면·합성이 예전과 똑같이 돈다(무대 메이크업 코드는 `stageMakeup` 이 있는 모드에서만 실행). 배경은 자동으로 돌아가지 않으니 화면 배경 목록에서 평소 배경을 다시 고른다(배경 추천 글꼴도 그 배경 것으로 바뀐다).

### 한계

- 부스 화면 자체는 한국어 전용이다(키오스크처럼 언어를 고르지 않는다). 행사 모드의 새 문구(대기 화면·룩 이름·설명·인화물)만 영어를 함께 쓴다.
- 메이크업은 얼굴 모양을 따라 그리는 것이라 실제 화장처럼 보이지만, 옆얼굴이 심하거나 손·머리카락이 이목구비를 가리면 그 부분은 어색할 수 있다. 실시간 화면은 전체를 한 번에 보기 때문에 멀리 선 작은 얼굴은 인화물에서만 입혀질 수 있다.
- 이용권(구매 특전) 흐름은 모드와 무관하게 그대로다 — 행사장에서 무료 체험으로 돌리려면 마스터 번호를 쓰거나 카운터 발급을 쓴다.
