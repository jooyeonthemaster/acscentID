# 포토부스 카운터 이용권

2026-09-24. 카운터에서는 키오스크와 포토부스가 보이지 않는다. 그래서 부스 이용량은 **직원이 결제 후 카운터에서 뽑아 주는 이용권 장수**로만 통제한다.

## 흐름

1. 손님이 카운터에서 결제한다.
2. 직원이 카운터 PC의 `/booth/counter` 화면에서 인원수 버튼(1~4장)을 누른다.
3. 영수증 프린터에서 이용권 쪽지(6자리 번호)가 한 장씩 나온다.
4. 손님이 부스에서 촬영 방식을 고른 뒤 번호를 입력한다. 한 번 쓰면 끝이다.

## 규칙

- **유효기간:** 카운터 발급분은 발급 당일 자정(KST)까지 쓸 수 있다. 자정 직전에 뽑아도 최소 2시간은 유효하다. 관리자 화면(`/admin/photobooth#events`)에서 발급한 것은 지금처럼 기한이 없다.
- **틀린 번호 잠금:** 없는 번호가 1분 안에 10번 입력되면, 매장의 모든 부스가 1분간 번호를 받지 않는다. 마스터 번호도 이때는 막힌다. 이미 쓴/취소된/만료된 번호를 다시 넣는 것은 틀린 입력으로 세지 않는다. 입력 기록을 읽지 못하면 잠그지 않는다(손님 흐름 우선).
- **카운터 기기 권한:** 카운터 PC는 관리자 로그인이 아니라 **카운터 PIN**으로 한 번 연결한다(180일 유지). 할 수 있는 일은 이용권 발급·다시 출력·오늘 발급분 취소뿐이다. PIN을 바꾸면 연결된 기기가 모두 풀린다. 관리자 계정으로 로그인한 브라우저에서도 이 화면을 쓸 수 있다.
- **다시 출력·취소:** 용지가 걸렸으면 목록에서 "다시 출력"을 누른다(같은 번호). 잘못 뽑았으면 "취소"를 누른다. 사용한 이용권은 취소되지 않는다.
- 관리자 이용권 목록에 발급처(카운터/관리자)와 기간 만료가 표시된다. 매출 건수와 대조할 수 있다.

## 배포 전 준비 (기기와 무관, 지금 가능)

1. **마이그레이션:** Supabase SQL 에디터에서 `supabase/migrations/20260924_photobooth_counter_passes.sql`을 실행한다. **코드 배포 전에** 실행한다 — 새 이용권 확인 코드가 `expires_at`을 읽기 때문이다. 기존 코드는 새 칸을 무시하므로 먼저 실행해도 안전하다.
2. **환경변수:** Vercel(Production)에 `PHOTOBOOTH_COUNTER_PIN`을 6자리 이상으로 설정한다. 없으면 카운터 기기 연결이 막힌다(관리자 로그인으로만 사용 가능).
3. **마스터 번호 교체 권장:** `PHOTOBOOTH_MASTER_CODE`(기본 110619)가 손님에게 알려지면 통제가 무너진다. 다른 6자리로 바꿔 두는 것을 권한다.
4. 배포 후 관리자 계정으로 `https://www.acscent.co.kr/booth/counter`를 열어 화면이 뜨는지 확인한다.

## 기기 도착 후 설치 (카운터 윈도우 PC + 80mm 영수증 프린터)

1. **프린터 드라이버 설치:** 제조사 드라이버를 설치하고, 인쇄 기본 설정에서 다음을 맞춘다.
   - 용지: 80mm 롤 (예: `80(72.1) x 297 mm` 또는 `Receipt`)
   - 자르기: **페이지마다 자르기(Cut per page / Page cut)** 켜기. 끄면 여러 장이 한 줄로 이어져 나온다.
2. **기본 프린터 지정:** 윈도우 설정 → 프린터 및 스캐너 → 영수증 프린터를 "기본값으로 설정"한다. "Windows에서 기본 프린터 관리"는 끈다.
3. **바로가기 만들기:** 이 저장소의 `scripts/counter-pc/install-counter-shortcut.ps1`을 PC로 복사해 실행한다.
   ```
   powershell -ExecutionPolicy Bypass -File .\install-counter-shortcut.ps1
   ```
   - 바탕화면과 시작 프로그램에 "포토부스 이용권 발급"이 생긴다. 크롬이 `--kiosk-printing`으로 떠서 **인쇄 창 없이 기본 프린터로 바로 출력**한다.
   - 전용 프로필을 쓰므로 평소 크롬과 섞이지 않는다.
   - 전체 화면으로 쓰려면 `-Fullscreen`을 붙인다.
4. **기기 연결:** 바로가기를 열고 카운터 PIN을 입력한다.
5. **시험:**
   - 목록 오른쪽 위의 "시험 출력"으로 쪽지가 한 장 나오는지, 글자가 잘리지 않는지 확인한다. 시험 쪽지 번호는 000 000이라 부스에서 쓸 수 없다.
   - 이어서 "1장 출력"으로 실제 이용권을 뽑아 부스에서 입력해 본다.
6. **쪽지 길이 조정:** 아래가 너무 남거나 잘리면 `src/app/booth/counter/CounterClient.tsx`의 `SLIP_HEIGHT_MM`(기본 90mm)을 바꿔 배포한다.

## 파일

- `supabase/migrations/20260924_photobooth_counter_passes.sql`: `expires_at`, `issued_via`, 틀린 입력 기록 테이블
- `src/lib/photobooth/passes.ts`: 발급·만료 계산 (관리자·카운터 공용)
- `src/lib/photobooth/counter-auth.ts`: 카운터 기기 PIN 연결
- `src/app/api/photobooth/counter/`: 연결(`route.ts`)과 발급·목록·취소(`passes/route.ts`) API
- `src/app/api/photobooth/pass/route.ts`: 부스 번호 확인 (기한·잠금 추가)
- `src/app/booth/counter/`: 카운터 화면과 쪽지 인쇄
- `node scripts/verify-photobooth-passes.mjs`: 메모리 DB 모형으로 연결·발급·사용·만료·잠금 검증 (운영 데이터 무관)
