# 키오스크 체험 18종 확장 (2026-10-14)

`Kiosk-Detailed-Flows-20261014` 목업의 비사진·비영상 결과물 체험 18종을 실제 입력·선택·결과·저장 화면으로 구현했다. 기존 10개 프로그램을 보존해 `/kiosk-demo`에서 총 28종을 연다. 추가 범위에서 포토부스, 전통 화가, 뮤직비디오, 추억 무비 등 사진·영상 결과물 제작형은 제외했다.

## 실행과 운영

```sh
npm run dev -- --webpack --port 3014
# http://localhost:3014/kiosk-demo
# http://localhost:3014/kiosk?mode=studio-sommelier
```

관리자 → 운영 모드에서 이름 검색 또는 종류별 필터로 고른다. 기존과 같은 기기별 저장을 사용한다. 미리보기의 `?mode=studio-…`는 저장된 운영 설정을 바꾸지 않는다. 브라우저 데모의 워터마크 정책도 기존대로 유지한다.

앱은 기존 체험과 동일한 560px CSS 폭을 기준으로 한다. 물리 키오스크는 기존 Electron 화면 배율 설정을 사용한다. 일반 데스크톱 브라우저의 큰 창에서는 가운데 정렬된다. 새 18종은 **한국어**이며, 기존 10종의 다국어 기능은 유지한다.

취향 추천은 입력에 반응하는 로컬 규칙과 실제 향료 목록을 사용한다. 새 생성형 AI API를 호출하거나 고정 결과를 AI 응답으로 가장하지 않는다. 조건에 맞는 후보가 없으면 선택을 유지하고 수정을 안내한다. 실제 여행지 영업시간·예약, 상품 판매/결제, 하드웨어 로봇 제어는 포함하지 않는다.

카메라 3종은 MediaPipe로 손/얼굴의 **존재**를 확인한다. 실존 연예인과의 얼굴 식별·유사도 계산, 실제 손금 선 추출, 외모에 기반한 성격·건강·운명 판정은 구현하지 않았다. 화면과 결과에 창작 체험의 기준을 설명한다. 사진은 브라우저 메모리에만 두며 결과 카드에 포함하지 않는다. 제품은 판매 상품이 아닌 조작 가능한 가상 디자인이고 문화유산 장면은 고증 복원 자료가 아닌 교육용 개념 재현이다.

## 공통 흐름과 저장

- 뒤로 가기·입력 수정·필수 항목 안내·후보 비교·전체 상세 가이드·도움말·처음으로 확인창을 제공한다.
- 모든 주요 CTA는 실제 버튼이며 이미지 안에 입력·문구를 구워 넣지 않았다. 삽화 18장은 내장 이미지 생성 도구로 새로 제작했다. WebP 총 약 3.5MB, 프롬프트는 `kiosk-expansion-art-prompts.json`, 원본은 로컬 `design-review/kiosk-expansion-art-originals`에 보관한다.
- 사용자가 저장용 QR 만들기를 누르면 전체 결과를 900px 폭 JPG로 렌더링해 기존 `/api/kiosk/share` 저장소에 업로드한다. 성공 응답을 받은 뒤 실제 다운로드 주소의 QR을 표시한다. 실패 시 입력/결과를 보존하고 다시 시도한다.
- 기존처럼 결과는 24시간 보관하며, 저장 주소는 `/kiosk/get/[token]`이다. 결과 캐시는 전체 내용별로 분리하며 만료 전에 새로 만든다. 처음으로 돌아간 뒤 늦게 완료된 업로드는 다음 방문자의 캐시에 들어가지 않는다.
- 새 결과 파일·화면에는 브랜드 문구를 넣지 않는다. 기존 결과 파일의 이름은 보존한다.
- 새 모드는 영수증 인쇄, 결제, `/api/kiosk/record` 분석 DB 기록을 추가하지 않는다. 휴대폰 저장만 업로드한다.
- 일반 화면의 무입력 만료는 기본 100초, 결과 120초, 저장 180초(일부 카메라/참여자 화면은 기존 `KX_IDLE` 값)다. 기존 셸이 10초 안내 후 초기화한다. 완료 화면은 15초 뒤 입력을 지운다.

## 연결 전시

1. 제품·문화유산·비전 월에서 **전시 연결 만들기**를 누른다.
2. 전시 기기의 브라우저에서 QR/주소를 연다. 주소는 `/kiosk-display/[room]#token=…`이다. 개발 시 전시 기기가 접근 가능한 LAN 호스트로 키오스크를 열어야 한다. 휴대폰/다른 기기의 `localhost`는 키오스크가 아니다.
3. 수신 창이 실제로 heartbeat를 보내야 키오스크에 연결됨이 뜬다. 전송 후 수신 화면이 렌더링하고 ACK를 보내야 완료된다. 요청 접수만으로 성공을 표시하지 않는다.
4. 연결은 종류별 `sessionStorage`에 남아 같은 브라우저의 다음 방문자도 재사용한다. 공개 비전 월은 최근 30개 메시지를 누적한다. 방문자 입력 초기화와 연결 수명은 별개다.
5. 연결은 생성 후 1시간 만료한다. 만료/권한 종료 시 수신 내용을 지우고 새 연결을 요구한다. 연결되지 않은 상태에서도 제품·문화유산은 키오스크 안에서 계속 체험할 수 있다.

제어 토큰과 수신 토큰은 별도 256비트 난수다. 서버에는 SHA-256 해시만 저장하며, API는 Bearer 토큰의 역할을 검사한다. 제어 토큰은 수신 URL에 포함하지 않는다. 콘텐츠·색·범위·길이 검증, 같은 요청 재시도의 중복 방지, 서버 revision 비교 갱신을 사용한다. 토큰 URL은 전시 접근 권한이므로 공개 홍보 링크로 배포하지 않는다.

## 프로덕션 반영 시 필요한 설정

이 브랜치는 로컬 구현·검증본이며 운영 사이트 배포나 운영 DB 변경을 실행하지 않았다.

- 기존 운영 게이트 `KIOSK_ENABLED=1`, 원격 키오스크라면 `KIOSK_ALLOW_REMOTE=1`을 유지한다.
- 기존 결과 공유용 Supabase 환경 변수와 `analysis-images` 저장소를 사용한다. 운영 키오스크가 로컬 Next 서버를 쓰는 경우에도 `NEXT_PUBLIC_SITE_URL`은 휴대폰에서 열리는 공개 사이트여야 한다. 운영에서는 이 설정을 우선하고, 개발 localhost에서만 현재 개발 주소를 쓴다.
- 연결 전시용으로 `supabase/migrations/20261014_kiosk_exhibit_rooms.sql`을 배포 DB에 적용해야 한다. 테이블 RLS를 켜고 공개 정책을 만들지 않는다. 서비스 역할 키는 서버에서만 사용한다.
- 개발에서는 `.data/kiosk-exhibit`의 실제 파일로 송수신을 검증한다. **프로덕션에는 파일/메모리 성공 응답 대체 경로가 없다.** 테이블이나 서버 자격 증명이 없으면 503 오류를 안내한다.
- 실제 현장 카메라, 터치패널, 네트워크, 전시 장비/창의 가시성, Electron 배율은 기기에서 최종 확인한다. 새 모드의 다국어는 별도 작업이다.

## 검증

```sh
npm run test:kiosk-expansion
npx tsc --noEmit
npm run build -- --webpack
```

33개 엔진/프로토콜 테스트: 모든 설문 문항의 결과 반영, 재료 제외·논알코올, 코디 조건, 여행 시간·실내 조건, 사람별 집계, RGB 오차, 토큰 역할·만료·ACK·중복·보관 개수.

브라우저 검증: 9종 설문 전체 왕복과 저장 실패/재시도, 5종 카메라/참여자 흐름, 4종 인터랙션과 실제 수신 ACK, 기존 7종 시작 화면 회귀, 18종 새 시작 화면과 28개 데모 링크·이미지. 실제 공유 서버 업로드·QR 해독·모바일 페이지·JPG 다운로드는 모두 HTTP 200으로 확인했다. 실제 MediaPipe 모델도 생성된 얼굴·손 이미지를 카메라 스트림으로 공급하여 촬영→JPEG→검출→결과까지 확인했다(얼굴 478점, 손 21점). 빈 화면 검출 실패·재촬영 복구·모델 503·권한 거절·카메라 트랙 종료·사진 미업로드도 확인했다. 생성 이미지 스트림 검증은 물리 카메라 검증과 구분한다.

구조: `src/lib/kiosk/expansion`에 데이터/규칙/전시 프로토콜, `src/app/kiosk/experience/expansion`에 실제 화면, `src/app/kiosk-display`에 수신 화면, `src/app/api/kiosk/exhibit`에 송수신 API가 있다. 등록은 기존 `experience.ts → modes.ts → ExperienceApp` 경로를 재사용한다.
