# 키오스크 체험 18종 확장 (2026-10-14)

`Kiosk-Detailed-Flows-20261014` 목업의 비사진·비영상 결과물 체험 18종을 실제 입력·선택·결과·저장 화면으로 구현했다. 기존 10개 프로그램을 보존해 `/kiosk-demo`에서 총 28종을 연다. 추가 범위에서 포토부스, 전통 화가, 뮤직비디오, 추억 무비 등 사진·영상 결과물 제작형은 제외했다.

## 실행과 운영

```sh
npm run dev -- --webpack --port 3014
# http://localhost:3014/kiosk-demo
# http://localhost:3014/kiosk?mode=studio-sommelier
```

관리자 → 운영 모드에서 이름 검색 또는 종류별 필터로 고른다. 기존과 같은 기기별 저장을 사용한다. 미리보기의 `?mode=studio-…`는 저장된 운영 설정을 바꾸지 않는다. 브라우저 데모의 워터마크 정책도 기존대로 유지한다.

앱은 기존 체험과 동일한 560px CSS 폭을 기준으로 한다. 물리 키오스크는 기존 Electron 화면 배율 설정을 사용한다. 일반 데스크톱 브라우저의 큰 창에서는 가운데 정렬된다. 새 18종은 **한국어**이며, 기존 10종의 다국어 기능은 유지한다.

취향 추천은 입력에 반응하는 로컬 규칙과 실제 향료 목록으로 후보를 만들고, AI 가 그 후보 중 하나를 골라 풀이한다(아래 'AI 분석과 이미지 합성'). 후보 밖의 상품을 지어내지 않고, 고정 결과를 AI 응답으로 가장하지 않는다. 조건에 맞는 후보가 없으면 선택을 유지하고 수정을 안내한다. 실제 여행지 영업시간·예약, 상품 판매/결제, 하드웨어 로봇 제어는 포함하지 않는다.

주거복지 내비게이터·성향 테스트(`NO_PHOTO_IDS`)를 뺀 체험은 모두 사진 한 장으로 시작한다(아래 '사진 한 장'). 실존 연예인과의 얼굴 식별·유사도 계산, 실제 손금 선 해석, 얼굴 생김새에 기반한 성격·건강·운명 판정은 하지 않는다(AI 지시문과 응답 검사로 막는다). 화면과 결과에 창작 체험의 기준을 설명한다. 촬영 사진은 AI 분석·합성 요청에만 보내고 저장하지 않으며, 결과 카드·영수증에는 촬영 사진 대신 AI 가 새로 만든 그림(6종)만 들어간다. 제품은 판매 상품이 아닌 조작 가능한 가상 디자인이고 문화유산 장면은 고증 복원 자료가 아닌 교육용 개념 재현이다.

## 공통 흐름과 저장

- 뒤로 가기·입력 수정·필수 항목 안내·후보 비교·전체 상세 가이드·도움말·처음으로 확인창을 제공한다.
- 모든 주요 CTA는 실제 버튼이며 이미지 안에 입력·문구를 구워 넣지 않았다. 삽화 18장은 내장 이미지 생성 도구로 새로 제작했다. WebP 총 약 3.5MB, 프롬프트는 `kiosk-expansion-art-prompts.json`, 원본은 로컬 `design-review/kiosk-expansion-art-originals`에 보관한다.
- 사용자가 저장용 QR 만들기를 누르면 전체 결과를 900px 폭 JPG로 렌더링해 기존 `/api/kiosk/share` 저장소에 업로드한다. 성공 응답을 받은 뒤 실제 다운로드 주소의 QR을 표시한다. 실패 시 입력/결과를 보존하고 다시 시도한다.
- 기존처럼 결과는 24시간 보관하며, 저장 주소는 `/kiosk/get/[token]`이다. 결과 캐시는 전체 내용별로 분리하며 만료 전에 새로 만든다. 처음으로 돌아간 뒤 늦게 완료된 업로드는 다음 방문자의 캐시에 들어가지 않는다.
- 새 결과 파일·화면에는 브랜드 문구를 넣지 않는다. 기존 결과 파일의 이름은 보존한다.
- 결과 화면 바닥은 기존 체험과 같은 **인쇄하기**(누르면 바로 영수증 — 사장님 지시 "원큐에 결과 확인하자마자 인쇄하기 버튼만 누르면") · **휴대폰으로 받기** 두 버튼이다(`TakeActions` — `KxReceiptSheet`·`KxSaveSheet`). 결제, `/api/kiosk/record` 분석 DB 기록은 추가하지 않는다. 업로드는 결과 카드(+ AI 합성 그림) 한 번뿐이고 둘이 같이 쓴다.
- 일반 화면의 무입력 만료는 기본 100초, 결과 120초, 저장 180초(일부 카메라/참여자 화면은 기존 `KX_IDLE` 값)다. 기존 셸이 10초 안내 후 초기화한다. 완료 화면은 15초 뒤 입력을 지운다.

## 사진 한 장 (2026-10-14 추가)

사장님 지시: "새롭게 추가된 프로그램들, 전부 키오스크에서는 영수증으로 결과를 받아갈 수 있게 해주고, 웬만해서는 전부 다 카메라를 활용해서 사진을 찍어 그 정보를 활용해 결과를 도출하는 데 쓰게 해줘".

- **흐름**: 18종 모두 안내 뒤 `PhotoStep`(안내 → 3초 촬영 → 확인 → 읽기 → '사진에서 읽은 것')을 지난다. 단체·커플은 가로 액자(4:3)로 찍고, 손금은 손을 찍는다. 확인 화면(취향·팀·커플)에서 사진을 다시 보거나 다시 찍을 수 있다.
- **읽는 것**(`src/lib/kiosk/expansion/photo.ts`, 기기 안 MediaPipe): 표정(blendshape — 미소·눈썹·입), 고개 기울기, 여러 얼굴의 수·거리·고개 방향, 옷 색(6분류 분할 모델의 '옷' 픽셀 → k-평균 → 흔한 이름), 사진 속 빛(배경의 밝기·노란빛), 손가락을 펼친 정도·엄지. **얼굴 생김새의 비율·피부색·나이·성별은 보지 않고, 얼굴과 이름을 짝짓지 않는다.**
- **쓰는 곳**: 취향 9종은 답변 점수 위에 사진 점수를 더한다(후보마다 최대 20~30점 안팎). 후보마다 '사진에서 읽은 것' 절에 무엇을 몇 점 더했는지 그대로 적고, 더하지 않았으면 그렇다고 적는다 — 같은 답변이라도 사진이 다르면 첫 후보가 달라진다(시험 있음). 스타 무드는 무드를 먼저 짚어 고르기 화면에 '사진과 어울려요'로 표시만 하고, 고르는 것은 손님이다. 손금은 펼친 정도로 먼저 펼칠 선을, 관상은 표정·기울기로 '오늘의 한마디'를 바꾼다(성격·운명 문장 없음). 팀·커플은 '사진 속 우리 팀/두 사람' 절과 옷 색 팔레트를 더한다. 빛 실험은 옷 색을 네 번째 미션으로, 조명·궁궐·비전 월은 첫 설정을 사진으로 고르고 그 까닭을 보여 준다(바꾸면 바꾼 값이 결과에 남는다).
- **문턱값**(시험 사진으로 맞춘 값, 실제 매장 조명에서 다시 볼 것): 입을 다문 옅은 미소가 70, 이를 드러낸 웃음이 94~96 → '환한 미소' 78 이상, '살짝 미소' 30 이상. 편하게 벌린 손이 검지·새끼 19° → 8°=모음, 40°=활짝. 아주 어두운 옷은 RGB 채도로 검정/네이비를 가른다(RGB 14·21·31 = 네이비). 개발 서버에서는 읽은 값이 콘솔 `[kiosk] 사진에서 읽은 값`에 찍힌다(운영 빌드에서는 찍지 않는다).
- **못 읽을 때**: 얼굴·손이 없으면 다시 찍기를 안내한다. 얼굴·손 도구(45초)·옷 분할 도구(16MB, 20초)를 받지 못하면 각각 안내하거나 옷 색 없이 진행하고 '옷 색: 이번에는 읽지 못했어요'라고 그대로 적는다. 사진이 체험의 중심이 아닌 15종은 '사진 없이 하기'가 있다(그때 결과에는 사진 이야기가 없다). 손금·관상·스타 무드는 사진이 있어야 한다.
- **받아 두기**: 첫 화면(손님 없음)에서 필요한 도구를 천천히(`preloadVision` 'idle') 받아 둔다. 퍼스널 컬러와 같은 보관함이라 매장 키오스크에는 옷 분할 모델이 이미 있을 수 있다.
- **검증(2026-10-14, 3014 개발 서버 · 가짜 카메라 영상 + 실제 MediaPipe · 저장은 가로챔 · 프린터는 가짜 브리지)**: 18종 모두 촬영 → 읽기(0.3~1.8초) → 모드 흐름 → 결과의 '사진에서 읽은 것' → 영수증 인쇄 → 휴대폰 QR(영수증과 같은 업로드 한 번) → 완료. 비전 월은 실제 수신 화면 ACK 까지(수신 화면에 사진 없음). 실패 경로: 얼굴 없는 사진 → 다시 찍기·사진 없이 하기(결과에 사진 이야기 없음), 한 사람만 나온 커플 사진 → 다시 찍기, 저장 실패 시 영수증은 QR 없이 인쇄되고 휴대폰 받기는 재시도로 QR, 다음 방문자에게 이전 사진 값 없음. 시험 54개(색 이름·k-평균·표정·손·거리, 같은 답변이라도 사진이 다르면 첫 후보가 달라짐, 세 표정 모두 점수 반영, 얼굴과 이름을 짝짓지 않음, 영수증에 사진 절 포함·촬영 사진 없음). 시험 사진은 생성 이미지라 실제 매장 카메라·조명 값과 다를 수 있다.

## AI 분석과 이미지 합성 (2026-10-14 추가)

사장님 지시: "전부 실제 API 호출을 활용해 분석 내지는 이미지 합성을 진행하도록 해". 합성 범위(사진이 주인공인 6종)와 개발 중 실제 유료 호출은 사장님이 골랐다.

- **AI 분석(18종 모두)** — `POST /api/kiosk/experience/expansion`(텍스트 모델 `OPENROUTER_TEXT_MODEL`, `generateParsed`). 사진(긴 변 768)·기기에서 잰 값·답변·후보(취향 9종은 로컬 규칙의 상위 4개)·모드 맥락을 보내면 `{pick, headline, insight, photo[], tips[]}`. 결과 맨 앞 절 'AI 분석 · {headline}'(화면 첫 절·카드·영수증). 취향 9종은 AI 가 고른 후보가 첫 결과가 된다. 팀·커플은 이름 대신 '참여자 N'만 보낸다. 3~7초.
- **응답 검사**(`src/lib/kiosk/expansion/ai.ts`) — 후보 밖 pick, 실존 인물·닮음, 손금·수명·운명, 외모·피부·체형·나이, 성격·됨됨이 단정('마음씨가 느껴져요'), 팀·관계 판정('최적의 구성')은 이유를 붙여 다시 받는다(최대 3번). 실호출에서 실제로 나온 표현으로 목록을 늘렸다.
- **이미지 합성(6종)** — `POST /api/kiosk/experience/expansion-image`(`generateKioskImage`, 장당 약 $0.04, 분 8장·하루 400장 상한을 다른 그림 기능과 함께 셈). 스타 무드 화보(고른 무드) · 오라 사진(AI 가 고른 컬러) · 타임머신 사진(장면·시대·빛, 옛 풍경이면 한복) · 커플/팀 포스터(정해 둔 관심사 장면 — 한국어 활동 이름을 넣으면 글자를 그려 넣고 거리 장면에 군중을 그려 영어 장면으로 바꿨다) · 코디 룩북(AI 가 고른 코디를 입힌 전신). 모든 지시문에 '사람을 바꾸지 말고, 연예인처럼 만들지 말고, 글자를 그리지 말 것'. 10~20초.
- **기다림·실패** — 'AI가 분석하고 있어요 → 이미지 합성' 화면(`AiWait`). 분석이 실패하면 가짜 결과 없이 오류 화면에서 다시 시도 또는 **AI 분석 없이 결과 보기**(그렇다고 결과 머리에 적는다). 합성만 실패하면 결과·인쇄는 되고 '다시 만들기'. 스타 무드는 다른 무드로 다시 만들기가 손님당 세 번까지.
- **비용 막기** — 분석은 서버 인스턴스당 분 30·하루 3000(`KIOSK_EXPANSION_DAILY_LIMIT`). 무인증 엔드포인트라 `kioskEnabled` 게이트와 길이·개수 검사가 있다.

## 영수증

결과 화면의 **인쇄하기**를 누르면 바로 찍힌다(키오스크 프린터 — `KxReceiptSheet`, 결과 카드 QR 이 같이 찍힌다). 프린터가 없는 브라우저에서는 미리보기와 PNG 저장. 내용(`src/lib/kiosk/expansion/receipt.ts`): AI 합성 그림(없으면 모드 그림, 점묘) · 요약 · 태그 · 지표 · AI 분석을 맨 앞으로 절 넷까지(목록은 다섯 줄까지) · '사진에서 읽은 것'(뒤쪽에 있어도 꼭) · 주의 문구. 잘린 내용이 있으면 '나머지는 휴대폰 카드에' 안내. 촬영 사진은 찍지 않는다(합성 그림이 있으면 '새로 만든 그림만 인쇄'라고 적는다). 길이는 25~32cm(AI 문단이 대부분).

## 연결 전시

1. 제품·문화유산·비전 월에서 **전시 연결 만들기**를 누른다.
2. 전시 기기의 브라우저에서 QR/주소를 연다. 주소는 `/kiosk-display/[room]#token=…`이다. 개발 시 전시 기기가 접근 가능한 LAN 호스트로 키오스크를 열어야 한다. 휴대폰/다른 기기의 `localhost`는 키오스크가 아니다.
3. 수신 창이 실제로 heartbeat를 보내야 키오스크에 연결됨이 뜬다. 전송 후 수신 화면이 렌더링하고 ACK를 보내야 완료된다. 요청 접수만으로 성공을 표시하지 않는다.
4. 연결은 종류별 `sessionStorage`에 남아 같은 브라우저의 다음 방문자도 재사용한다. 공개 비전 월은 최근 30개 메시지를 누적한다. 방문자 입력 초기화와 연결 수명은 별개다.
   수신 화면은 카드의 실제 크기를 재서 겹치지 않게 배치한다(`wall-layout.ts`): 가장 최근 카드는 고른 자리에, 앞선 카드는 가까운 빈자리로 옮긴다. 자리가 모자라면 가장 덜 겹치는 곳에 둔다.
5. 연결은 생성 후 1시간 만료한다. 만료/권한 종료 시 수신 내용을 지우고 새 연결을 요구한다. 연결되지 않은 상태에서도 제품·문화유산은 키오스크 안에서 계속 체험할 수 있다.

제어 토큰과 수신 토큰은 별도 256비트 난수다. 서버에는 SHA-256 해시만 저장하며, API는 Bearer 토큰의 역할을 검사한다. 제어 토큰은 수신 URL에 포함하지 않는다. 콘텐츠·색·범위·길이 검증, 같은 요청 재시도의 중복 방지, 서버 revision 비교 갱신을 사용한다. 토큰 URL은 전시 접근 권한이므로 공개 홍보 링크로 배포하지 않는다.

## 프로덕션 반영 시 필요한 설정

이 브랜치는 로컬 구현·검증본이며 운영 사이트 배포나 운영 DB 변경을 실행하지 않았다.

- 기존 운영 게이트 `KIOSK_ENABLED=1`, 원격 키오스크라면 `KIOSK_ALLOW_REMOTE=1`을 유지한다.
- 기존 결과 공유용 Supabase 환경 변수와 `analysis-images` 저장소를 사용한다. 운영 키오스크가 로컬 Next 서버를 쓰는 경우에도 `NEXT_PUBLIC_SITE_URL`은 휴대폰에서 열리는 공개 사이트여야 한다. 운영에서는 이 설정을 우선하고, 개발 localhost에서만 현재 개발 주소를 쓴다.
- 연결 전시용으로 `supabase/migrations/20261014_kiosk_exhibit_rooms.sql`을 배포 DB에 적용해야 한다. 테이블 RLS를 켜고 공개 정책을 만들지 않는다. 서비스 역할 키는 서버에서만 사용한다.
- 개발에서는 `.data/kiosk-exhibit`의 실제 파일로 송수신을 검증한다. **프로덕션에는 파일/메모리 성공 응답 대체 경로가 없다.** 테이블이나 서버 자격 증명이 없으면 503 오류를 안내한다.
- 실제 현장 카메라, 터치패널, 네트워크, 전시 장비/창의 가시성, Electron 배율은 기기에서 최종 확인한다. 새 모드의 다국어는 별도 작업이다.
