# 키오스크 · 부스 영상 흐름 — 끊김 없이 잇기

손님이 어느 때 버튼을 눌러도 **컷 없이, 빈 화면 없이, 2초 안에** 다음 장면으로 걸어가는 영상 화면을 만든다. 2026-11-18 SIP! 소믈리에 영상판에서 만들어 확인한 방법이다(본보기 코드 `src/app/kiosk/experience/expansion/SipMotion.tsx`, 기록 `docs/nh-awards-demo.md` 「조각 영상으로 다시 짬」).

## 핵심 원리 — 이 셋만 지키면 끊기지 않는다

1. **같은 그림에서 시작해 같은 그림에서 끝난다.** 장면마다 그림 한 장(장소 그림)을 정하고, 그 장면의 모든 조각 영상의 첫 프레임과 끝 프레임에 그 그림을 넣어 만든다. 이동 영상은 첫 프레임 = 떠나는 장면 그림, 끝 = 도착 장면 그림. 그러면 어느 조각 끝에서든 다음 조각으로 이음매 없이 붙는다(실측 평균 차이 1.3~3.0/255).
2. **조각은 짧게(4초), 넘김은 영상이 끝날 때.** 장면에 머무는 영상을 하나의 긴 반복 영상으로 만들면 가운데가 그림에서 멀어져 중간에 끊고 나갈 수 없다. 4초 조각이면 버튼을 누른 뒤 남은 몫을 최대 2배로 마저 틀어 2초 안에 이동 영상으로 넘어간다. 넘기는 시점은 `ended` — 계산한 시간(setTimeout)으로 넘기면 영상이 조금만 늦어도 중간에 잘려 튄다.
3. **다음 영상은 미리 받아 두고, 첫 프레임이 그려진 뒤에 보인다.** 그동안 앞 영상이 마지막 프레임을 붙들고 있어 빈 화면이 없다.

장면 하나의 흐름:

```
이동 영상(걸어 들어옴) → hi 인사 동작(4초, 한 번) → idle 대기(4초 × 2가지 무작위) … ─버튼→ 지금 조각 마저(≤2초) → 이동 영상(걸어 나감 → 길 → 다음 장면으로 걸어 들어옴) → 다음 장면 hi …
```

마무리 동작은 따로 만들지 않는다 — 이동 영상 앞부분(인물이 돌아서 걸어 나감)이 마무리다. 따로 넣으면 이동마다 그만큼 길어진다.

## 순서

### 1. 지금 상태 보기
- 이미 영상판이 있으면 그 영상들이 중간에서 끊을 수 있는지부터 잰다: `node scripts/check-video.cjs <mp4 폴더> profile <영상 이름…>` — 가운데 값이 5 를 크게 넘으면(15~34 였다) 긴 반복 영상 구조라 조각으로 다시 만들어야 한다.
- 부스 영상판(`src/app/booth/programs/video-stage.tsx`, FACE! 관상 등)은 2026-11-18 기준 장면마다 긴 반복 영상(loops) + 연결 영상(moves) 구조다 — 이 스킬을 적용하려면 `loops` 를 조각(hi · idle)으로 바꾸고 재생 부분을 references/player.md 구조로 바꾼다. 다른 세션이 작업 중일 수 있으니 `git log` · `git status` 로 먼저 본다.

### 2. 설계 — 표로 정리해 사용자에게 보이고 정한다
- 장면 목록과 차례, 장면마다 장소 그림(첫 · 끝 프레임), 그 장면에서 할 인사 동작, 대기 두 가지, 장면 사이 이동(누가 어느 쪽으로 걸어 나가고 들어오는지).
- 비용: 조각 수 × 길이 × 단가. Wan 3.0 720p 는 4초 0.30달러(목록 단가 초당 0.10달러보다 낮게 청구됐다), 1080p 는 4초 0.48~0.60 · 8초 0.96달러, 한 개 약 104~200초. 장면 6개 × 3조각(720p) = 5.40달러였다. `--dry` 로 어림한다.
  (이 파일에는 달러 기호 뒤에 숫자를 바로 쓰지 않는다 — 스킬을 부를 때 인자 자리 표시로 바뀐다.)
- 키: 프로젝트가 정해졌으면 그 프로젝트 키, 실험 · 데모는 R&D 키(`OPENROUTER_KEY_RND`) — **어느 키로 만들지 사용자에게 확인**하고 시작한다(CLAUDE.md 키 규칙). 키 값은 찍지 않는다.
- 그림이 아직 없으면 그림부터(인물 시트를 먼저 만들고 그 시트를 넣어 같은 얼굴 · 옷 유지). 원본은 저장소 밖 `design-review/<프로그램>-art/`.

### 3. 만들기
1. spec.json 을 쓴다 — 형식은 `scripts/wan-clips.mjs` 머리말, 예는 `examples/sip-beats.json`, 프롬프트 틀은 **references/prompts.md**(인사 · 대기 · 이동 문장, 화풍 꼬리, 인물 없는 프로그램).
2. `set -a; . ~/.config/openrouter/keys.env; set +a` 뒤 `node scripts/wan-clips.mjs spec.json --dry` 로 개수 · 비용 확인.
3. **한 개 먼저**(`--only hi-<첫 장면>`) 만들어 밀착 인화로 본다 — 요청 형식 · 화풍 · 자세가 맞는지. 맞으면 나머지를 백그라운드로(동시 6개, 이미 있는 것은 건너뜀).
4. 원본은 `outDir` 에 남기고(`_log.jsonl` 에 비용), 화면용은 `scripts/encode.sh <원본 폴더> public/assets/<…>` — 소리 빼고 720×1280 · 30fps · H.264 crf 23 · faststart(4초 조각 하나 300~700KB).

### 4. 확인 — 눈과 숫자 둘 다
- 자세 · 얼굴: `scripts/sheet.sh 출력.jpg hi-x.mp4 idle-x-1.mp4 idle-x-2.mp4` 를 장면마다 만들어 **직접 본다**(Read). 얼굴 · 옷 · 소품이 같은지, 마지막 칸이 첫 칸 자세로 돌아왔는지.
- 이음매: `node scripts/check-video.cjs <화면용 폴더> seams …` 로 이어 붙는 모든 짝을 잰다 — 장면마다 `hi>idle-1 hi>idle-2 idle-1>idle-2 idle-2>idle-1 idle-1>idle-1`, 떠날 때 `hi>move-다음 idle-1>move-다음`, 도착 `move-x>hi-x`. 5 이상(!!)이면 그 조각만 다시 만든다.
- 이동 영상은 0.5초 간격 밀착 인화로 out(인물이 다 나간 초) · in(들어오기 시작한 초)을 재서 재생기 표에 넣는다.

### 5. 재생기 붙이기
**references/player.md** 를 읽는다 — [앞 · 지금 · 다음] 세 겹, 다음 조각 고르기, Film(첫 프레임 뒤 보이기 · 마저 틀기 빠르기 · 이동 빠르기 · 안전 타이머), 도착 알리기, 그리고 실제로 밟은 함정 표. 가장 빠른 길은 `SipMotion.tsx` 를 복사해 표(PIC · MOVE · 장면 차례 · IDLES)만 바꾸는 것. 화면 글자(대사 · 제목)는 도착(onSettle) 뒤에만 띄우고, 떠날 때 대사판은 살짝 가라앉으며 사라지게.

### 5-1. 말하는 조각(대사 · 목소리 · 립싱크)
**references/voice-lipsync.md** 를 읽는다. 대사 → `scripts/voice-sync.mjs tts` → `stt` 로 발음 확인 → `lipsync`(Sync.so) → 소리 든 mp4. 키는 이 저장소 `.env.local` 의 `ELEVENLABS_API_KEY` · `SYNC_API_KEY`(스크립트가 스스로 읽음). 결과에 소리가 있으니 `encode.sh`(소리 뺌)로 줄이지 않는다.

### 6. 실제 화면 검사
- `npx tsc --noEmit -p .` · 바꾼 파일 eslint.
- 개발 서버(이 저장소는 보통 3014 에 떠 있다 — `lsof -iTCP -sTCP:LISTEN -P | grep node`)에서 `node scripts/timeline.cjs 시나리오.json [스크린샷 폴더]` — 예 `examples/sip-timeline.json`. 버튼을 장면 조각의 앞 · 중간 · 끝 여러 때에 누르게 delay 를 섞는다.
- 통과 기준: **빈 프레임 0**, 누른 뒤 이동 영상까지 **2초 이하**(같은 장면 안 버튼 줄은 무시), 차례가 hi → idle … → move → hi 로 이어짐, 콘솔 오류 없음.
- NAV 가 두 번 넘게 찍히면 개발 서버가 파일 바뀜(다른 세션 작업 포함)으로 페이지를 새로 고친 것 — 조용할 때 다시 돌린다.
- 사용자에게 보여 줄 때는 `open -a "Google Chrome" <주소>` 로 띄우고 볼 곳(누른 직후 · 걸어 나갈 때 · 도착할 때)을 짚어 준다.

### 7. 정리
- 화면에서 안 쓰게 된 옛 영상은 public 에서 뺀다(원본은 design-review 에 남았는지 확인 후).
- 그림 · 영상 폴더 README 와 그 프로그램 문서(docs/…)에 조각 구성 · 비용 · 이음매 수치 · 대기 시간 · 도구 위치를 적는다.
- 커밋 · 배포는 사용자가 말할 때. 이 저장소는 main push 가 곧 운영 배포다.

## 스크립트

| 파일 | 하는 일 |
|---|---|
| `scripts/wan-clips.mjs <spec.json> [--dry] [--only a,b] [--jobs 6]` | 첫 · 끝 프레임을 넣어 영상 생성(오픈라우터), 단가 · 길이 검사, 어림 비용, 이미 있으면 건너뜀 |
| `scripts/encode.sh <원본|폴더> <내보낼 폴더> [가로 세로 crf]` | 화면용 인코딩(소리 빼기) |
| `scripts/sheet.sh <출력.jpg> <영상…>` | 밀착 인화(영상 하나 한 줄, 0.5초 한 칸) |
| `scripts/check-video.cjs <폴더> seams a>b … \| chain a b c \| profile a …` | 실제 Chrome 으로 이음매 · 첫 프레임과의 거리. 폴더를 직접 띄워 개발 서버가 필요 없다 |
| `scripts/timeline.cjs <scenario.json> [스크린샷 폴더]` | 프로그램을 눌러 가며 매 프레임 기록 — 대기 시간 · 빈 프레임 |
| `scripts/voice-sync.mjs voices\|tts\|stt\|lipsync …` | ElevenLabs 목소리 · 받아쓰기, Sync.so 립싱크(소리 든 mp4). 자세히는 references/voice-lipsync.md |
| `scripts/ff.sh` | ffmpeg 찾기(없으면 ~/.cache/kiosk-video-flow/venv 에 imageio-ffmpeg 설치) |

Playwright 는 `~/.npm/_npx` 에서 찾고, H.264 때문에 설치된 Google Chrome(`channel: 'chrome'`)으로 돈다.
